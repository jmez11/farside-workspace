# Progress: Farside Workspace

## Current Status (2026-10-06)
- **Zoomed pointer input accuracy & selection targeting**: Pointer input is captured via an unscaled screen-space overlay `Box` (`Modifier.fillMaxSize().pointerInteropFilter`) layered over `AndroidView`. Raw screen coordinates `(eventX, eventY)` are inverted through `mapScreenToDesktop`: `tx = (eventX - panX - w/2f) / zoom + w/2f; ty = (eventY - panY - h/2f) / zoom + h/2f; rdpX = (tx * actualWidth / w); rdpY = (ty * actualHeight / h)`. The right-click hold indicator renders at unscaled screen coordinates directly over the controller pointer ray dot. Dragging selection boxes and right-click positioning are accurately targeted across all zoom levels (1.0x to 3.0x). On-device test `zoomTest` instrumented on Quest across 6 zoom levels (1.0x, 1.25x, 1.42x, 1.5x, 2.0x, 3.0x) confirmed unscaled screen coordinates delivered with zero drops. `inputOnly` passed gesture timing, double-tap tolerance, controller scrolling, and zoomed mapping.
- **Quest keyboard Enter key**: Intercepted `KEYCODE_ENTER` in `RemoteImeEditor.kt` via `Modifier.onPreviewKeyEvent`, dispatching single XT scancode `0x1C` down/up and consuming the key event. Newline characters (`\n`) in `BasicTextField.onValueChange` are debounced within 200ms to guarantee exactly one remote Enter event.
- **App-wide PIN & Credential Protection**: Single App-wide PIN configured in Settings (Tunnels & Global) App Security (salted PBKDF2-SHA256/600k encrypted by Keystore). Credentials feature a "Require PIN" toggle without per-credential PIN fields. Toggling off Require PIN on an existing protected credential enforces entering the App PIN before setting to no. Enabling Require PIN requires an App PIN configured. Sessions with Require PIN enabled gate connection startup on entering the App PIN; unprotected credentials launch directly. Credential edit/delete do not prompt for a PIN. On-device `credentialsOnly` passed on Quest.
- **Spatial Audio**: Audio streams explicitly set `AAudioStreamBuilder_setSessionId(b, AAUDIO_SESSION_ID_ALLOCATE)` in `quest_audio.cpp` ensuring independent spatial audio localization per session window. User verified 3D audio origin in space (2026-10-06). Verified and closed.
- **Display Resolution Setting**: Removed "Customize Display Resolution" setting and submenu from `LauncherUI.kt` per user request.
- **Password Security & Management**: Saved passwords use randomized AES-GCM via Android Keystore (`CredentialManager`); credentials excluded from cloud backup. Edits start with blank password field (blank preserves, typing replaces). User Management supports Edit/Save/Cancel with UUID persistence.
- **Proxy Options**: Limited to None, Cloudflared, SOCKS5, and HTTP (SOCKS5/HTTP mark unavailable and reject RDP). Bundled arm64 `cloudflared` binary with loopback proxy and browser handoff verified on Quest.
- **RDP Certificates & Diagnostics**: Platform X509 trust manager and OpenSSL identity verification with photo-matched warning dialog and persistent leaf fingerprint exceptions.
- **Keyboard Extra Keys**: Separate attached spatial window (76dp/314dp), unshifted desktop surface with `adjustNothing`, synchronized compositor compaction/reveal (`KeyboardPanelResize.kt`), dual `RemoteImeEditor` native focus handoff.
- **Display Resize Height Parity**: Masked height to even with `& ~1` in `Java_com_farside_workspace_FreeRDPBridge_updateDisplay` matching width, ensuring MediaCodec I420 chroma subsampling requirements are met and preventing decode failure on odd-height resizes.

- **SSH Session Floating Toolbar, Zoom & Extra Keys**: Added movable, auto-disappearing floating toolbar matching RDP design with connection name/host, pin toggle, zoom button with font size slider (8sp-32sp) and Reset Zoom button, and keyboard toggle button. Added soft keyboard IME integration with dual `RemoteImeEditor` instances without shifting main content window (`adjustNothing`). Integrated `RemoteKeyboardPanel` bottom-anchored companion spatial window (76dp collapsed, 314dp expanded via `123`/`ABC` toggle) with full extra keys bank (`RemoteExtraKeys` with Ctrl, Alt, Shift latches, arrows, Home/End, PgUp/PgDn, Ins/Del, F1-F12, keypad, arithmetic, and number swap), dynamically sending VT codes and Unicode points to `sshTerm` and resizing PTY window dimensions via `Session.Shell.changeWindowDimensions`.
- **SSH Keys, PIN Protection & 5-Minute Cache**: Added "SSH Keys" tab in Settings to create, edit, and delete saved SSH keys (`SavedSshKey.kt`). Both private key and optional passphrase are encrypted with randomized AES-GCM via non-exportable Android Keystore key; zero plaintext in SharedPreferences or disk XML. Keys support "Require PIN" toggle gated by the App PIN (disabling requires entering current App PIN; enabling requires App PIN configured). In connection profile setup, SSH profiles allow choosing saved SSH keys from a dropdown, and credentials are fully optional (host is sufficient; user, pass, and key are optional). When credentials are omitted, `SshTerminalSession` falls back to interactive terminal login (`login as: ` and password prompt). All PIN unlock dialogs include an initially unchecked "Don't reprompt for 5 minutes" checkbox; upon successful unlock, PIN is held in a thread-safe in-memory `CharArray` cache in `CredentialPin.kt` with automatic memory zeroization upon 5-minute expiry or manual invalidation, bypassing unlock prompts during that window.
- **RDP Camera Redirection (`rdpecam`) & Hardware H.264 Encode**:
  - Implemented hardware-accelerated H.264 encoding via Android NDK `AMediaCodec` (`camera_encoding.c`), replacing software conversion stubs.
  - Negotiates `CAM_MEDIA_FORMAT_H264` (`0x0001`, `Flags = 0x01` / `CAM_MEDIA_TYPE_DESCRIPTION_FLAG_DecodingRequired`) as the preferred compressed camera media format with dynamic resolutions up to 1080p (`1920x1080`) and dynamic bitrate curve (700 kbps @ 480p up to 2.7 Mbps @ 1080p), with fallback to uncompressed NV12 (`Flags = 0x00`).
  - Quest Camera2 HAL NV12 frames are delivered directly into `AMediaCodec` (`COLOR_FormatYUV420SemiPlanar` / 21) with low-latency mode and 1s I-frame intervals, producing Annex B H.264 NAL units streamed over RDP dynamic virtual channels to remote Windows Media Foundation decoders.
  - Resolved resolution negotiation: Sorted advertised media types descending by pixel area in `camera_android.c` so target resolutions (720p/1080p) take precedence, and updated default media type selection in `camera_device_main.c` to pick the highest resolution matching `cam_android_get_max_dimension()` instead of hardcoding 640x480.
  - Fixed green cast on bottom rows of video frames: Added explicit `stride`, `slice-height`, `crop-left`, `crop-top`, `crop-right`, and `crop-bottom` parameters to `AMediaFormat`, initialized extra padding memory in `AMediaCodec` input buffer to neutral black (UV=128, Y=0), and initialized newly allocated `nv12Buffer` memory to neutral black.
  - Floating hoverbar persistence during active recording: Kept floating hoverbar permanently visible while `cameraRecording` or `micRecording` is active by tying `isMediaRecording` into `MainActivity.kt`'s auto-fade effect and triggering `revealToolbar()` immediately upon capture start.
  - Verified on-device with `live-nucbox`: remote Windows host negotiated `CAM_MEDIA_FORMAT_H264`; verified SD, HD_720, and FHD_1080 resolution profiles cleanly; `AMediaCodec` encoder initialized cleanly and streamed encoded H.264 frames to `webcamtests.com` in real time with PASS status.
  - Connections default to camera disabled (`enableCamera = false`); enabling camera redirection requests `android.permission.CAMERA`, `horizonos.permission.HEADSET_CAMERA`, and `horizonos.permission.AVATAR_CAMERA` via system permission prompt. Removed connection setup camera dropdown, redirecting all enumerated backward-compatible cameras with descriptive names: front lens-facing camera `1` is registered as `"Virtual Camera"`, and back lens-facing camera `50` as `"Passthrough Camera"`.
  - Added camera resolution selector (`CameraResolution`: `SD` (480p), `HD_720` (720p), `FHD_1080` (1080p)) directly below "Redirect Camera" switch in RDP profile setup (`LauncherUI.kt`), disabled when camera redirection is off. Enforces max advertised resolution cap (`cam_android_set_max_dimension`) on device streams to cap video capture and H.264 encode appropriately.
  - Fixed Quest passthrough room camera (`50` / `"Passthrough Camera"`) by configuring capture requests with `TEMPLATE_RECORD` instead of `TEMPLATE_PREVIEW`, matching Quest Camera2 HAL driver requirements.
  - Closed launcher `MainActivity` upon launching session window (`SessionWindowLauncher.launch(...)`), ensuring Horizon OS anchors the avatar virtual camera viewport directly to the active session window.
  - Floating menubar webcam icon (`RdpCameraControl`): turns red when remote applications are capturing frames, supports muting (blackout NV12 frames), and displays a red circle-slash prohibition symbol when camera redirection is unsupported on host (e.g. Windows Home/Core on `LAPTOP-BBJV33M6`), with a non-dismissible explanation dialog.
- **Debug Actions in Settings**: Added debug-only section under Settings (Tunnels & Global) visible only in debuggable builds (`FLAG_DEBUGGABLE`). Includes "Clear Trusted Certificates" to wipe all saved RDP certificate fingerprint exceptions via `RdpCertificateStore.clearAll()`, and "Revoke Granted Permissions" utilizing `context.revokeSelfPermissionsOnKill()` (Android 13+ / API 33+) to revoke camera, headset camera, avatar camera, microphone, and read storage permissions upon next process kill.
- **SSH Session Cloudflared Proxy**: Extended `CloudflaredTunnel` and `SshTerminalSession` to support SSH connections over Cloudflare Access (`cloudflared access ssh --hostname <host> --url 127.0.0.1:<port>`). In connection profile editor, Cloudflared is selectable and validated for SSH profiles. When enabled, `SshTerminalSession` launches the bundled arm64 `cloudflared` binary with `access ssh` and private loopback listener, streams real-time status into the terminal view, binds SSHJ transport to the local proxy port, and terminates the tunnel cleanly on session teardown.
- **RDP Remote Storage Redirection (`rdpdr` + `drive`)**: Static virtual channel client drive redirection implemented using FreeRDP's `rdpdr` and static `drive-client` extension. Connections default to storage disabled (`redirectStorage = false`). Toggling "Redirect Storage" in connection profile setup or launching a storage-enabled session checks `hasStoragePermission(context)` (`Environment.isExternalStorageManager()`) and prompts the user for All Files Access via `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`. External storage root (`/sdcard`) is announced and mounted under share name `"Quest"`. Storage runs headless in the background of active RDP sessions and is explicitly excluded from the floating menubar (preserving menubar space for mic and camera controls). FreeRDP JNI bridge maps `drive_DeviceServiceEntry`, adds filesystem device to settings collection in `client_pre_connect`, tracks `rdpdr` connected/disconnected state via PubSub, and exposes `isStorageConnected`.

  - **RDP**: Registered FreeRDP `cliprdr` static virtual channel (`FreeRDP_RedirectClipboard` and static channel loading via `freerdp_channels_client_load_ex`). Implemented JNI bridge methods `sendClipboardText` and `isClipboardConnected`, and Kotlin callback `onNativeClipboardChanged`. Wired Android `ClipboardManager.OnPrimaryClipChangedListener` and `FreeRDPBridge.clipboardListener` in `RdpSessionScreen` with echo-suppression loops.
  - **SSH**: Wired `TerminalView` copy and paste callbacks in `MainActivity.kt`. Selecting text in the terminal copies directly to Android `ClipboardManager` as plain text. Pasting reads text from the Android system clipboard and transmits UTF-8 bytes directly to the active `TerminalSession`.
  - **Clipboard Character Truncation Bug Fix**: Resolved an issue where remote RDP clipboard text was truncated down to a single character. WinPR's `ConvertWCharNToUtf8` expects a destination buffer with capacity for a null terminator when sizing; passing the exact byte count caused the conversion to return `-1`, which fell back to treating UTF-16LE data as ASCII/UTF-8 where the second byte (`\0`) truncated the string after index 0. Replaced manual buffer calculations in `ServerFormatDataResponse` and `ServerFormatDataRequest` with `ConvertWCharNToUtf8Alloc` and `ConvertUtf8ToWCharAlloc`, added CRLF line ending normalization for Windows RDP hosts, and verified proper string conversion on-device.
