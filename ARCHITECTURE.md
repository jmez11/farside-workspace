# Architecture: Farside Workspace

## Product Vision
**Farside Workspace** is a native RDP and SSH client for Meta Quest (Horizon OS). Its defining feature is that every remote session and RemoteApp is its own spatial window, which can be placed freely in the standard Home/passthrough environment without entering a custom VR world. It is designed as a plain-language, no-bells-and-whistles productivity utility.

## Project Identity
- Repository/Gradle project: `farside-workspace`; product: Farside Workspace; Android application/namespace: `com.farside.workspace`. Kotlin sources and JNI symbols share that namespace. Local checkout: ``C:\dev\farside-workspace``. Runtime storage/Keystore/session URI names use ``farside``; bundled Cloudflared and its parser share ``FARSIDE_*`` process markers and the ``2026.5.1-farside`` version. Renaming the package creates a separate installation without migrating the previous app data.

## Module Map
1. **App / UI Layer (`app`)**: Jetpack Compose and Meta VR Layout SDK for Compose Spatial Windows. Manages the connection launcher (main panel) and spawns new Spatial Windows for each session.
2. **Session Manager**: Coordinates active connections, handles panel lifecycle (spawning/closing windows), and routes input. Responsible for deciding whether to spawn a new FreeRDP instance or mirror an existing session's video decode.
3. **RDP Core (`freerdp-jni`)**: JNI bridge to FreeRDP 3.27.1+. Handles session lifecycle, video stream decoding (MediaCodec AVC/H.264), input event injection, RAIL window mapping, and camera redirection (`rdpecam`).
4. **SSH / Terminal Core (`ssh-core`)**: SSHJ for secure transport, combined with Termux's GPLv3 terminal-emulator stack for VT100/xterm emulation. Dynamic PTY window resizing via `sshShell.changeWindowDimensions(columns, rows, width, height)`. Floating movable toolbar with 3-second auto-fade, pin toggle, zoom font size adjustment (`8sp..32sp`), reset zoom, and keyboard toggle matching the RDP design. Bottom-anchored companion spatial window (`RemoteKeyboardPanel`, 76dp/314dp) with full `RemoteExtraKeys` modifier latching, VT escape sequences, and dual `RemoteImeEditor` text routing while preserving the main terminal window's geometry (`adjustNothing`). Supports public key authentication using saved SSH keys, password authentication, and interactive terminal login fallback when credentials or keys are not provided.
5. **Settings & Storage**: Saved credential/profile/proxy passwords and SSH private keys/passphrases use randomized AES-GCM encryption via a non-exportable Android Keystore key (`CredentialManager`); app-private preferences store ciphertext, with plaintext legacy fields migrated in one durable transaction by `ProfileManager`. `SavedSshKey.kt` encrypts both private keys and optional passphrases with Keystore. Key usage requires no biometric prompt. Credentials, SSH keys, and preferences are excluded from cloud backup and device transfer because the key is device-bound. Passwords and keys are decrypted in app memory only when authenticating; hashing cannot replace recoverable credentials. Credential and key editing never preloads saved passwords/passphrases into input fields: blank preserves existing values, new text replaces them. Masked inputs request password keyboard type with autocorrect disabled; password state is not saved in Activity instance state.
6. **Network & Proxy Subsystem**: Saved RDP profiles support Cloudflared via `CloudflaredTunnel.kt`: one bundled child per session, private loopback listener, authentication preflight and browser handoff. `CloudflaredService` reuses the runtime for explicit foreground-service forwarding; persistent settings/management, SSH tunnels and arbitrary proxy commands remain incomplete.

## Windowing Model
- **Proxy choices**: Only None, Cloudflared, SOCKS5 and HTTP are selectable. SOCKS5/HTTP remain unimplemented: saved proxy fields are not passed through `FreeRDPBridge`/JNI. `RdpSessionConnection` rejects them rather than connecting directly. SOCKS4/LOCAL/TELNET enum values remain only for legacy profile decoding; UI requires a supported selection before saving and RDP rejects those legacy configurations. Cloudflared's existing runtime remains active. Harness: `-e proxiesOnly true` verifies actual Compose choices/selection, legacy decoding and no direct TCP fallback using a loopback listener. It does not establish SOCKS5/HTTP protocol support or physical Horizon interaction.
- **App-wide PIN & Credential/SSH Key Protection**: Settings (Tunnels & Global) App Security configures one App-wide PIN (4–12 digits plus confirmation). Users can change or remove the PIN after entering the current App PIN. Individual credentials and saved SSH keys feature a simple "Require PIN" toggle without item-specific PIN fields. Toggling Require PIN off on an already protected credential or SSH key prompts for the App PIN prior to setting it to false; enabling Require PIN requires an App PIN to have been configured first. Launching a session whose linked credential or SSH key has Require PIN enabled gates connection startup on entering the App PIN. Sessions without Require PIN set do not prompt for a PIN to launch. Credential and SSH key edit and delete actions do not prompt for a PIN. `CredentialPin.kt` stores a random-salt PBKDF2-HMAC-SHA256 verifier (600,000 iterations, [OWASP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)), encrypted with the existing Keystore key in `app_pinVerifier` preferences; PIN text is never persisted. Five failures start a persistent 30s backoff, escalating to 5min. `CredentialPinDialog.kt` verifies off the main thread with masked numeric input. All PIN unlock dialogs include an initially unchecked "Don't reprompt for 5 minutes" checkbox; when selected, a successful unlock caches the PIN in an in-memory `CharArray` for 5 minutes (thread-safe, automatically zeroized upon expiry or explicit logout/invalidation) and bypasses subsequent prompts during that window.
- **Saved credentials & SSH keys**: User Management supports Edit/Save Changes/Cancel Edit, retaining the credential UUID. Settings "SSH Keys" tab supports adding, editing, and deleting saved SSH keys with multiline private key input, optional passphrase, and Require PIN gating. `ConnectionProfile.credentialId` and `ConnectionProfile.sshKeyId` persist profile links. SSH connection profiles do not require credentials; username, password, and SSH key are optional, falling back to interactive terminal login when omitted. Harness: `adb shell am instrument -w -e sshKeysOnly true com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation` validates in-memory PIN cache expiry and memory wiping, AES-GCM ciphertext persistence, optional SSH credentials, Settings SSH Key management, PIN toggle protection with 5-minute checkbox, wrong PIN rejection, 5-minute prompt bypass, and profile SSH key dropdown selection. `credentialsOnly` validates credential lifecycle, App PIN setup/backoff, and session gates.
- **Spatial Windows**: Built using the VR Layout SDK. The main app panel acts as a connection manager. Connecting to a host spawns a new independent Spatial Window.
- **RAIL Support**: Each RemoteApp published via RAIL appears as its own floating window, with server-authoritative z-order and transparency support.
- **Lifecycle**: Closing a session terminates its connection. FreeRDP's event-loop exit reports Error Info, last-error text or a disconnect ultimatum through a per-bridge JNI callback. An established session shows a non-dismissible Disconnected dialog with the available reason; OK closes its Activity. Local teardown suppresses that callback, and ended sessions do not reconnect on surface replacement. Mirrored-window shutdown remains planned.
- **Remembered placement**: `SessionWindowPlacement.kt` stores observed position+quaternion per profile ID/session ordinal in app-private `session_window_positions` preferences; stop/destroy flush the final pose. The launcher allocates the lowest free ordinal, checking active windows/tasks (including restored tasks), and requests the saved pose with Horizon ActivityOptions. The Activity also makes one unprivileged transaction request on first resume for direct launches. Home may adjust/deny requests; absent APIs or rejected options fall back to ordinary placement. No global window-management permission is requested. Two simultaneous windows of one profile keep separate slots, reused when reopened. Room/recenter continuity is not guaranteed. [Meta transaction policy](https://developers.meta.com/vr/reference/metavr-os-jsdk/v207/class_metavr_app_volumetricwindow_volumetric_window_manager/).

## Input Pipeline
- **Quest Controllers**: Raycast to window coordinates and translated into RDP mouse events.
- **RDP gestures**: Controller trigger/hand pinch arrive as Android touch events. The clockwise square stays hidden for 0.5 seconds, then draws over the next second. A stationary hold of at least one second sends right-click on release; short taps click left and motion beyond touch slop starts left drag. `inputOnly` checks indicator timing at the delay/drawing/completion boundaries.
- Nearby second touch taps within Android's double-tap timeout reuse the first click position within twice touch slop, allowing ray jitter while the remote OS still owns double-click recognition. Drag/hold/mouse input and cancellation clear the candidate; drag threshold stays unchanged. `inputOnly` checks diagonal/radius/time boundaries and cancellation.
- **Keyboard**: Meta IME plus `RemoteExtraKeys.kt`: Win, Shift, Ctrl, Alt, AltGr, Del, Esc, Tab, 123. First five latch RDP down/up with teal held indicators and release on IME closure. `123` opens the second level below the strip and changes to `ABC` to close it: F1-F12, right-click at the last remote pointer position, Print Screen, Backspace, keypad Enter/arithmetic, and Home/End/Page/Insert/Delete/Enter/arrows. Number Keys swaps the function bank for digits/decimal; Function Keys restores it. Expansion preserves held modifiers; narrow panels scroll. Extended RDP scancodes distinguish right Alt/Win/navigation/keypad keys.
- **Quest keyboard Enter key**: `RemoteImeEditor.kt` intercepts `KEYCODE_ENTER` via `Modifier.onPreviewKeyEvent`, dispatches the single XT Enter scancode (`0x1C`) down and up, and consumes the event. Newline characters (`\n`) in `BasicTextField.onValueChange` are debounced within 200ms to guarantee exactly one remote Enter event is sent instead of duplicate enters.
- RDP stays a full-size desktop in `SpatialScene`, with `adjustNothing` to prevent IME resize/pan. `RemoteKeyboardPanel.kt` emits a width-matched `SpatialWindow` attached parent Bottom/child Top, sized 76dp/314dp for strip/123. Desktop texture size/origin, remote resolution and Home pose stay unchanged; unavailable placement drops the companion rather than altering the desktop. Content fades/retracts over 180ms. Compaction finishes the bank animation, briefly fades/masks the child at compositor level, then changes its size. `KeyboardPanelResize.kt` waits for a hardware frame-commit callback at the compact height plus two frame boundaries before revealing it; this prevents the previous expanded buffer being drawn at the new compact pose. The same hosted surface/editor persists, preserving IME focus. Meta-style regular sans-serif, dark colors, 8dp key corners/strip spacing and 12dp padding remain.
- `RemoteImeEditor.kt` prepares invisible real text editors in both desktop and key surfaces. Native focus selects the active InputConnection. Each editor prepares focus once; pointer activation waits three frames for native binding and leaves a focused/active editor alone. Explicit show is reserved for initial desktop opening or a keyboard still hidden after a short recovery delay. Input restart/focus reset are recovery only, never routine surface handoff. Keycaps cannot take text focus. IME visibility is observed in both windows, with a 600ms stable-hide grace for focus handoff before removing the companion; explicit toolbar close remains immediate. Internal key-window focus does not reveal the desktop toolbar. No nonfocusable-surface hack or global window permission ships.
- Desktop touches activate its IME editor while the keyboard is requested; otherwise they focus desktop input. Both editors forward text/backspace to the same FreeRDP session. Extra-key latches release on keyboard/session closure.

## Camera Redirection (`rdpecam`)
- Uses Horizon OS Passthrough and Avatar Camera API (`android.permission.CAMERA`, `horizonos.permission.HEADSET_CAMERA`, and `horizonos.permission.AVATAR_CAMERA`).
- Default: Connection profiles default to camera redirection disabled (`enableCamera = false`). Toggling on requests camera permissions via Quest system dialog.
- Camera picker dropdown is removed from connection setup; all enumerated backward-compatible cameras are redirected to the session.
- Descriptive naming: FRONT lens-facing cameras are registered and passed as `"Virtual Camera"` (avatar/selfie camera); BACK/EXTERNAL lens-facing cameras are registered and passed as `"Passthrough Camera"` (room cameras).
- Framerate prioritization: Caps advertised NV12 resolutions to max 640x480 (640x480, 640x360, 320x240) with 30fps target AE range, preventing high uncompressed resolutions from bottlenecking framerate over RDP dynamic virtual channels. Uses `TEMPLATE_RECORD` for Quest Camera2 HAL capture session compatibility. Launcher window closes upon session launch to ensure Horizon OS avatar selfie viewport anchors directly to the active session window.
- Floating menubar webcam icon (`RdpCameraControl`):
  - Turns red while remote applications are actively capturing/recording video from the redirected camera (`cam_android_is_recording()`).
  - Toggling mute streams blackout NV12 frames while preserving the active virtual channel.
  - If remote host fails or does not support camera redirection (e.g. Windows Home/Core or license 0), shows red circle-backslash prohibition overlay. Selecting the icon displays an alert dialog: "This host does not support camera redirection."
- Host capability detection: verified via `RdpHostCapabilities` (reading Windows edition / license policy in `rdp-host-capabilities.json`) and dynamic virtual channel negotiation (`RDCamera_Device_Enumerator` handshake status).
- Media Foundation MFT Compatibility: FreeRDP's `camera_device_main.c` is overridden in `app/src/main/cpp/` via CMake. Uncompressed NV12 media types explicitly send `Flags = 0` per MS-RDPECAM 2.2.3.6 (avoiding `CAM_MEDIA_TYPE_DESCRIPTION_FLAG_DecodingRequired = 0x01` which triggers Windows Media Foundation MFT "used or blocked by another application" rejection).
- Camera Harness: `adb shell am instrument -w -e cameraMode <mode> com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`. Modes include `live-nucbox` (live browser streaming test against `webcamtests.com`), `live-laptop` (unsupported RDPECAM detection on `LAPTOP-BBJV33M6`), `capabilities` (permission sets & profile defaults), `muted-ui`, `recording-ui` (red icon verification via PixelCopy), `blocked-ui`, and `hardware-probe`.

## Remote Storage Redirection (`rdpdr`)
- Client drive redirection via FreeRDP `rdpdr` static virtual channel with static `drive-client` extension.
- Default: Connection profiles default to storage redirection disabled (`redirectStorage = false`).
- Permission: Enabling "Redirect Storage" in the profile editor checks `hasStoragePermission(context)` (`Environment.isExternalStorageManager()`); if ungranted, launches `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` for "All files access". Launching a session with `redirectStorage = true` prompts for permission before connecting.
- Presentation: Mounts Android external storage root (`/sdcard`) under share name `"Quest"`. Runs headless in the session and is explicitly excluded from the floating menubar (reserving toolbar controls for mic and camera).
- Harness: `adb shell am instrument -w -e storageMode <mode> com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`. Modes include `capabilities` (intent generation, default values, JSON serialization and ProfileManager persistence), `ui` (permission launcher callback), `live-nucbox` (live RDP session with storage redirection against `nucbox`), and `live-laptop`.

## Security
- **Cloudflared**: fixed Android arm64 executable in nativeLibraryDir, argv-only ProcessBuilder, validated DNS hostname, and extra-parameter allowlist: service-token ID+secret or Cloudflare Access authentication headers. Reject the whole input on unknown/unsafe options; users cannot override listener/hostname/executable, inject shell commands, select files, dump traffic or disable TLS. Saved parameters are Keystore AES-GCM encrypted. HOME/token cache/transfer keys live under `noBackupFilesDir/cloudflared` (0700; upstream tokens 0600); child stdout/stderr and authentication URLs are not logged. Android trust anchors are atomically exported for Go TLS.
- Quiet Access login preflight handles valid credentials, cached JWTs and interactive login before RDP handshake timeout. Its standard encrypted Cloudflare transfer flow retrieves/caches user tokens; ACTION_VIEW opens only HTTPS transfer URLs for the profile hostname with the expected CLI path/query. The bundled source adaptation tolerates a missing CF-Access-Domain header using the original hostname, still requiring an audience. Routes without Access metadata proceed to the normal verified WebSocket handshake. Closing/failure cancels that session's child; surface replacement retains it. Listener readiness comes from a post-bind marker, with bounded startup/authentication waits. Original RDP host/certificate verification stays active through loopback.
- **RDP certificates**: FreeRDP `VerifyX509Certificate` uses external management; ignore-certificate and legacy RDP security fallback are disabled. JNI sends the full PEM chain to `RdpCertificateVerifier`; Android's default X509 trust manager checks server trust/validity and OpenSSL checks DNS/IP identity against the original profile host (not a tunnel's loopback endpoint).
- Unverifiable certificates show Connect/Cancel, an unchecked remember option, reasons and expandable issuer/dates/SHA-256 details. App-private `rdp_certificates` preferences persist the exact leaf fingerprint and PEM/details per case-insensitive host+port. Matching saved exceptions are reused only after attempting verification; a changed invalid certificate prompts again and shows the prior fingerprint. Valid replacements pass without an exception. Session-only Connect never updates trust; Cancel/dismiss rejects. Session disposal cancels a pending confirmation before worker teardown.
- **Credentials**: Stored in the Android Keystore.
- **NLA/CredSSP**: FreeRDP must be built with `WITH_INTERNAL_MD4`, `WITH_INTERNAL_RC4`, and `WITH_INTERNAL_MD5` to ensure NLA succeeds.
- **SSH**: Trust On First Use (TOFU) host-key verification.

## RDP Audio
- **Spatial Audio**: AAudio streams explicitly set `AAudioStreamBuilder_setSessionId(b, AAUDIO_SESSION_ID_ALLOCATE)` in `quest_audio.cpp` to ensure an independent audio session per stream. Horizon OS binds each session's 3D playback source to its own spatial window. User verified audio originates from the correct window in space (2026-10-06).
- FreeRDP owns `rdpsnd`/`audin` negotiation and DSP; `quest_audio.cpp` supplies Android AAudio PCM devices. Static `rdpdr`/`rdpsnd` load through `LoadChannels`; `audin` loads only for a microphone-enabled, permitted connection. Playback always redirects to Quest, independent of the legacy saved sound-redirection field.
- Setup checks `RECORD_AUDIO`; enabling the mic requests permission and denial leaves it off. A saved mic-enabled session waits for the permission result before creating its surface/connection, then connects without capture if denied. This override does not rewrite the saved profile.
- Toolbar speaker mute always appears; mic mute appears for effective microphone-enabled sessions. Mute sends silence per session. The mic turns red only while unmuted and the capture backend receives samples after a remote recording request; channel registration alone does not indicate recording. Capture stops on channel closure/session teardown.
- Confirmed unsupported capture shows a white mic with a red circle/slash; selecting it opens the host-support message and leaves mute unchanged. Host evidence is read from app-private `files/rdp-host-capabilities.json`, matching the profile host against verified aliases and a successful Windows `TSAudioCaptureAllowed=0` result. Missing evidence/idle capture stays unknown, with normal mute controls; actual capture clears a stale blocked state for that session. RDP has no general idle-host capture-support advertisement, so silent refusal cannot be automatically classified from a timeout.

## Threading Model & Performance
- A full-frame TextureView scales via Compose `Modifier.graphicsLayer { scaleX = zoom; scaleY = zoom; translationX = panX; translationY = panY }`. To bypass `ViewFactoryHolder` bounds-clipping of scaled coordinates at high zooms, touch input is captured on an unscaled screen-space overlay `Box` (`Modifier.fillMaxSize().pointerInteropFilter`). Screen pointer coordinates `(eventX, eventY)` are inverted through `mapScreenToDesktop`: `tx = (eventX - panX - w / 2f) / zoom + w / 2f; ty = (eventY - panY - h / 2f) / zoom + h / 2f; rdpX = (tx * actualWidth / w); rdpY = (ty * actualHeight / h)`. The right-click hold indicator draws in unscaled screen coordinates directly under the controller pointer ray dot. Drag touch-slop uses standard physical touch slop. After a 300 ms debounce, DisplayControl requests matching remote resolution.
- Home panel pose observation uses the headset framework's activity-scoped volumetric window listener, loaded reflectively for Android compatibility. Position/orientation changes reveal the session toolbar; registration is removed on Activity destruction. IME insets control the keyboard modifier row and hidden text-field lifecycle.
- Surface recreation replaces the native surface while retaining the connection. Session disposal joins native network/render workers before freeing the context.
- **Codecs:** FreeRDP 3.x static channels load through `LoadChannels` and a custom addin provider. Hardware AVC444v2 decoding through Qualcomm's low-latency MediaCodec decoder is verified on Quest 3. AVC444 reconstruction and YUV/RGBA conversion remain CPU work; Progressive/RemoteFX software decoders remain available.
- **Codec logging:** `RdpContext` owns the original SurfaceCommand handler and 16 atomic throttle counters, constructed/destructed with the native context and reset on GFX channel connection. GDI owns `RdpgfxClientContext::custom` as `rdpGdi*`; the wrapper recovers its session through `gdi->context`. Codec log lines include the session pointer.
- **MediaCodec implementation:** `app/src/main/cpp/h264_mediacodec.c` replaces the upstream experimental backend through the root CMake configuration; the FreeRDP submodule stays unchanged. Supports padded I420/NV12 output, bounded waits, and lazy decoder allocation. Only I420 output has been exercised on-device.
- **Build:** arm64 only; native debug builds retain symbols and use `-O2` so codec/conversion performance is representative.
- **Target:** 2-4 concurrent sessions on Quest 3. Background throttling remains planned.

## Phased Build Plan

**Build-ordering rule: De-risk first.** The highest-risk item is the FreeRDP NDK build and the JNI bridge. This must be spiked and validated before anything else.

### Spike Phase: JNI & Native Bridge
- **Goal**: Successfully compile FreeRDP 3.27.1+ via Android NDK and render a single session frame to an Android Surface.
- **Gotchas**: Set `HOME` env dir to `filesDir` before init; compile with internal crypto flags.
- **Acceptance**: A rudimentary Android activity connects to an RDP server and renders the desktop.

### Phase 1: Basic RDP
- **Goal**: Connect to one Windows PC, full desktop in a spatial window, mouse/keyboard input, securely saved credentials.
- **Acceptance**: Shippable single-session RDP client on Horizon OS.
- **Deferred**: Multiple sessions, RemoteApp, Webcam, SSH.

### Phase 2: Multiple Sessions
- **Goal**: N concurrent RDP sessions.
- **Implementation**: Allow user choice when reconnecting to an active host:
  - *New Independent Session*: Spawns a new FreeRDP instance (requires server CALs or multiple accounts).
  - *Mirror Session*: Spawns a new Spatial Window observing the same video decode stream from an existing session.
- **Acceptance**: Two desktop windows visible simultaneously in passthrough.

### Phase 3: RemoteApp Support (RAIL)
- **Goal**: Individual remote applications appear as their own floating windows.
- **Acceptance**: Launching a RemoteApp opens a new Spatial Window without the full desktop background.

### Phase 4: Webcam Support
- **Goal**: Redirect Quest cameras into the RDP session (`rdpecam`).
- **Acceptance**: Remote Teams/Zoom can access the Meta Avatar virtual webcam or room camera.

### Phase 5: SSH Windows
- **Goal**: Terminal sessions alongside RDP windows.
- **Acceptance**: SSH connection opens a window running the Termux VT emulator.

### Phase 6: Tunneling & Proxies (RDP Cloudflared implemented)
- **Goal**: Support RDP/SSH through Cloudflared, SOCKS5 and HTTP, plus persistent Cloudflared tunnels; connection choices are limited to None/Cloudflared/SOCKS5/HTTP.
- **Implementation**: Saved RDP Cloudflared uses the bundled Android arm64 binary, authenticated loopback forwarding and session-owned teardown. Persistent-service settings/device validation, SOCKS5/HTTP routing and SSH integration remain pending. Arbitrary commands are not selectable.
- **Acceptance**: Functional None/Cloudflared/SOCKS5/HTTP choices per connection and persistent Cloudflared foreground services.

## Open Decisions & Resolutions
- **App Name**: Resolved as **Farside Workspace**.
- **Phase 2 (Multiple Sessions)**: Resolved to support **both** true independent sessions and duplicated/mirrored sessions, depending on user choice at launch time.
- **Business Model & SSH Emulator**: App will be **Open-Source (Paid in store)**. Therefore, we will use the **Termux (GPLv3)** stack for terminal emulation, which provides superior emulation and is compatible with an open-source model.
