# Architecture: Farside Workspace

## Product Vision
**Farside Workspace** is a native RDP, SSH and VNC client for Meta Quest (Horizon OS). Its defining feature is that every remote session and RemoteApp is its own spatial window, which can be placed freely in the standard Home/passthrough environment without entering a custom VR world. It is designed as a plain-language, no-bells-and-whistles productivity utility.

## Project Identity
- Repository/Gradle project: `farside-workspace`; product: Farside Workspace; Android application/namespace: `com.farside.workspace`. Kotlin sources and JNI symbols share that namespace. Local checkout: ``C:\dev\farside-workspace``. Runtime storage/Keystore/session URI names use ``farside``; bundled Cloudflared and its parser share ``FARSIDE_*`` process markers and the ``2026.10.5-farside`` version. Renaming the package creates a separate installation without migrating the previous app data.

## Module Map
1. **App / UI Layer (`app`)**: Jetpack Compose and Meta VR Layout SDK for Compose Spatial Windows. Manages the connection launcher (main panel) and spawns new Spatial Windows for each session.
2. **Session Manager**: Coordinates active connections, handles panel lifecycle (spawning/closing windows), and routes input. Spawns one FreeRDP instance per RDP session.
3. **RDP Core (`freerdp-jni`)**: JNI bridge to FreeRDP 3.32.1 (`bf217a504e54cc719880c228e82353382cd7d4fa`; submodule tracking branch `3.32.x`). Handles session lifecycle, video stream decoding (MediaCodec AVC/H.264), input event injection, RAIL window mapping, and camera redirection (`rdpecam`). Upstream tag is unmodified; the former pin's local Android CMake fixes are no longer needed by this build.
4. **SSH / Terminal Core (`ssh-core`)**: SSHJ for secure transport, combined with Termux's GPLv3 terminal-emulator stack for VT100/xterm emulation. Dynamic PTY window resizing via `sshShell.changeWindowDimensions(columns, rows, width, height)`. Floating movable toolbar with 3-second auto-fade, pin toggle, zoom font size adjustment (`8sp..32sp`), reset zoom, and keyboard toggle matching the RDP design. Bottom-attached companion spatial window (`RemoteKeyboardPanel`, 251.2dp tall, minimum 512dp wide) with full `RemoteExtraKeys` modifier latching, VT escape sequences, and shared `RemoteImeEditor` text routing while preserving the main terminal window's geometry (`adjustNothing`). Supports public key authentication using saved SSH keys, password authentication, and interactive terminal login fallback when credentials or keys are not provided.
5. **Settings & Storage**: Saved credential/profile/proxy passwords and SSH private keys/passphrases use randomized AES-GCM encryption via a non-exportable Android Keystore key (`CredentialManager`); app-private preferences store ciphertext, with plaintext legacy fields migrated in one durable transaction by `ProfileManager`. `SavedSshKey.kt` encrypts both private keys and optional passphrases with Keystore. Key usage requires no biometric prompt. Credentials, SSH keys, and preferences are excluded from cloud backup and device transfer because the key is device-bound. Passwords and keys are decrypted in app memory for connection/vault operations; hashing cannot replace recoverable credentials. Credential and key editing never preloads saved passwords/passphrases into input fields: blank preserves existing values, new text replaces them. Masked inputs request password keyboard type with autocorrect disabled; password state is not saved in Activity instance state.
6. **Network & Proxy Subsystem**: Saved RDP/SSH/VNC profiles support HTTP CONNECT, SOCKS5 CONNECT and Cloudflared. RDP passes proxy settings to FreeRDP; VNC passes a connected Java socket FD to LibVNCClient for standard and Mac authentication; SSHJ uses `HttpConnectSocketFactory` or `Socks5SocketFactory`. `CloudflaredTunnel.kt` owns one child and private loopback listener per session. Persistent developer ADB access uses `AdbTunnelService`. Arbitrary proxy commands and persistent general-purpose tunnels remain unimplemented.

## VNC / Screen Sharing
- Diagnostic boundary: EOF at the initial12-byte banner read in `MacHevcSession.doAuthAndClientInit` or `VncBridge.authenticateApple` precedes VNC authentication; a ready SSH relay alone does not establish that its target Screen Sharing service is reachable. Quest3 wearer-retry evidence: `build/verification/jeff-vnc-diagnosis/live-private.txt` (Oct22).
- `libvncserver` is an unmodified upstream git submodule at `app/src/main/cpp/libvncserver`, pinned at `98aaee0560baa0332339b2ef464ea96ed9b9b28c` (0.9.15 plus upstream fixes); `vnc/CMakeLists.txt` builds client-only static LibVNCClient into `vnc-jni`. Software ZRLE/zlib/Tight decode; libjpeg-turbo 3.1.2 is pinned and built separately through ExternalProject (no MediaCodec). Upstream GPLv2 license and JPEG notices ship under `assets/licenses`.
- `vnc_bridge.cpp` owns each client's framebuffer, input queue, password, two ZlibHex streams, native window and worker/render threads. Only the worker accesses the RFB decoder/socket; completed frames copy to a protected RGBA buffer paced at 30fps. Cursor shape/mask/hotspot and position are session-owned and composited into the window buffer, preserving decoded desktop pixels. A fallback arrow covers peers such as macOS that omit cursor shapes; explicit zero-sized shapes hide it. Surface replacement is synchronized; disconnect signals/shuts down the socket, joins both threads, then frees client/window/JNI refs. `VncBridge` serializes handles with teardown; callbacks post to Android's main thread.
- Request order: ZRLE, Tight, ZlibHex, then Hextile/RRE/Raw. Generated upstream source copies add bounded ZlibHex decoding, reject non-type-2 security on the legacy path, and fix partial-field socket reads. NewFBSize reasserts pixel format/encodings before a full replacement frame, including same-size resets after Mac login. The Apple account path completes type-30 RFB 3.8/DH/MD5/AES authentication in Kotlin using platform crypto, then passes the authenticated socket to LibVNCClient at ClientInit. The type-2 path remains native and retains its 1 to 8 Latin-1 password rule; no-auth and types 33/35/36 are never selected.
- Generic VNC connection failures use the localized protocol failure message without Mac Screen Sharing/ARD guidance (`-e vncFailureOnly true` closed-loopback callback check). VNC profiles default to5900, with `vncAuthMode` and optional `sftpPairProfileId`. New setup chooses MAC_USER; legacy mode remains read-tolerant. Use a complete SavedCredential reference or explicit connection-specific username/password (Keystore-encrypted); `credentialSource` prevents new inline pairs auto-linking to matching vault entries while retaining legacy snapshot migration. Missing saved references fail rather than falling back. Mac mode requires username/password; VNC password mode requires1-8 Latin1 characters. New pairing choices are SFTP-enabled SSH; an existing disabled pair is retained for compatibility. Files hides when its pair is missing/SFTP-disabled. Required errors appear after navigation/Save attempts; invalid fields, proxies and routes cannot save.
- Secure Mac console unlock is not implemented. Live DH/RSA1 probes with Apple `003.889`/enhanced ClientInit still showed the existing user's lock screen; that host's SessionSelect path requires a different authenticated/console UID. Its credential-bearing SessionSelect command is not an established unlock operation for the current console. Type-33 retest after host settings change (2026-10-13) again authenticated successfully with flags=2 and remained locked after five seconds without input (`build/verification/vnc-lock/retry-type33/`). Do not substitute automatic password keystrokes. See `build/verification/vnc-lock/findings.md`; `macLogin` below is synthetic UI login, not protocol-level unlock.
- `VncSessionScreen` uses `DesktopSessionScreen`/`DesktopSessionBridge`, the existing RDP unscaled pointer overlay/inverse zoom-pan map, `RdpPointerGesture`, `RdpControllerScroll`, floating toolbar and shared IME/key panel. The existing Compose pointer observer forwards unpressed Move/Enter events to VNC; pointerInteropFilter does not provide these hover events through its touch callback. XT events translate to X11 keysyms (WIN = Command/Super); Unicode uses RFB Unicode keysyms. The shared toolbar adds Files only for an existing paired SSH profile; audio/camera/RDP storage/RemoteApp controls are absent for VNC. Server framebuffer resizes are followed; local window resizing scales rather than changing Mac resolution.
- Mac/VNC Review → General exposes Redirect clipboard, default on through the existing profile/JSON field. VncSessionScreen honors it; disabled Apple streaming sends no monitoring/fetch/text and suppresses incoming clipboard delivery. `macClipboardFixture` covers enabled and disabled control paths.
- Standard VNC uses bidirectional Latin-1 cut-text with optional extended UTF-8. Mac streaming uses Apple monitoring/fetch/zlib pasteboard archives for Unicode plain text over encrypted control, bounded to1MiB outbound text/32MiB incoming archives with record fragmentation and session-scoped Android echo suppression. Native Mac VNC fallback cannot share its modern pasteboard; images/files are unsupported. Details, references and `vncMode macClipboardFixture`: [Mac clipboard](docs/mac-clipboard.md). Cloudflared reuses the session child/loopback lifecycle with `access tcp`.
- `NetworkScanner.scanLocalNetworkForVnc(Context)` browses `_rfb._tcp.` for5s with serialized resolves/cancellation/removal. Setup discovers RDP or VNC only for the chosen protocol, including VNC password mode; SSH has no finder. Protocol switches cancel stale scans. Selection fills name/IP/advertised port. mDNS stays on the LAN; no VLAN/Tailscale discovery or credentials are implied.
- Harness: `adb shell am instrument -w -r -e vncMode fixture|picker|discovery|live|macPicker|pointer|macSetup|macShortUser|macPairSetup|macWrong|macLogin|danglingPair [-e vncProfile <id>] com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`. `macShortUser` probes Apple account auth with the short SSH username; `macPairSetup` updates the named saved credential, creates a same-Mac SSH profile, and pairs it to VNC. `macWrong` asserts rejected SecurityResult and the localized session callback; `macLogin` logs in using the saved credential and captures the desktop; `danglingPair` uses a disposable VNC profile to assert the Files action is absent when SSH is deleted. `fixture` exercises real JNI type-2 rendering/input/clipboard on test-only servers. Cache: `vnc-results.txt`, `vnc-frame-<encoding|live>.png`, `vnc-login-*.png`. Synthetic input does not establish physical keys/gestures or wearer appearance.
- Reset fixtures assert format/ordered-encoding negotiation before full requests, both same-size and growing framebuffers, then full/partial ZRLE rendering with a persistent zlib stream (`vnc-reset-*.png`). Opt-in `vncMode login` is a diagnostic for the known <MAC> 1280x800 account chooser; `vncPassword` supplies the transient macOS account password for this mode only, without saving/logging it. It captures the transition, rejects a black desktop, opens/closes a Finder window with synthetic Command keys and asserts both redraws (`vnc-login-*.png`). Do not run login/pointer modes against an already logged-in desktop or a different account layout.

- `VncSessionConnection` borrows `SshConnectionManager` by the selected SSH profile ID, sharing the terminal/files transport while owning only its relay channel/lease. In-memory Perl helper uses SSH exec framing, not a dynamic/SOCKS proxy; bounded startup, EOF/close cleanup and 600s expiry. Its readiness-driven nonblocking reactor separates control writes from media stdout pressure, preserves TCP half-closes and bounds media to512 packets/4MiB without truncating partial framing records. Production companion SSH always terminates on the viewed Mac; UDP binds loopback. The diagnostic helper retains an explicit target mode. UDP5901 is video/RTCP; UDP5900 audio/control, not a port per display. `MacMediaUdpSocket` owns one kernel listener per fixed headset port with bounded session queues; each pipeline authenticates its own SRTP keys before decoding. This avoids SO_REUSEADDR receiver stealing between concurrent Macs and SSH loopback relays. `VncBridge` has no global single-stream gate; only its own active session is guarded. Each session retains its own control authentication, relay, SRTP keys and decoder. Closing a subscription preserves other streams; the last releases the port. **Cloudflare same-Mac targeting**: always discover the origin on the SSH host, resolving its default-route interface IPv4 and validating locality separately from the loopback relay listeners. Legacy missing/false `macSshRelaySameMac` values deserialize as true; the obsolete Remote Login checkbox is removed. No addresses are hardcoded. Each helper is owned by its SSH exec channel: normal close sends a termination frame, stdin EOF exits, and600s without owner input expires. There is no process-list/PID singleton; exclusive UDP binds reject a competing owner on the same address/ports. An orphan can block startup until released; this does not establish desktop flicker as a helper problem. Diagnosis harness `-e vncMode macRelayDiagnosis -e vncProfile <id>`; `-e relayMedia true -e relayLan true` is a diagnostic-only explicit interface probe. No addresses hardcoded.
- `VncBridge` owns `MacHevcSession`: advertised RSA1 type33, else DH type30; experimental SRP stays off. Optional SessionSelect uses a **500ms** absent-header probe; a partial header retains the normal read deadline and fails if truncated. Bootstrap sends the media offer and immediately starts the continuous encrypted control reader; it does not wait for a batch of ten replies/heartbeats. Removed fixed 100/200ms handshake sleeps, and initial display scaling is1x to match subsequent resizes instead of allocating a temporary4K canvas. `MacSavedPasswordInput`/`MacUnlockControl` provide a once-only, confirmed toolbar action after Mac authentication on streaming **and ordinary VNC fallback**. It types into the user-selected empty own-account password field; authentication alone has not been shown to bypass the Mac lock screen.
- `MacMouseInput` retains held buttons across motion and emits wheel press/release without losing them. `MacPointerQueue` coalesces pending motion while preserving original press/release coordinates, scroll ticks and key barriers. TCP_NODELAY on control/relay sockets and a 16ms AVC drain interval avoid Nagle/sparse-frame stalls; low-latency MediaCodec mode is requested when supported. Hardware AVC assembly is bounded (4MiB units; 300ms/4096-packet/8MiB reorder window) with duplicate exclusion and validated SSRC retirement. After loss/input starvation, AVC holds the last clean image until IDR; recovery FIR requests have a500ms minimum interval. Identical pure-motion hover duplicates are removed before queuing, while edges/wheel/changed positions remain intact. Numeric relay/media and debug encrypted-input counters support latency diagnosis. [SSH latency findings and harness](docs/mac-ssh-latency.md).

## Security
- **Cloudflared**: fixed Android arm64 executable in nativeLibraryDir, argv-only ProcessBuilder, validated DNS hostname, and extra-parameter allowlist: service-token ID+secret or Cloudflare Access authentication headers. Reject the whole input on unknown/unsafe options; users cannot override listener/hostname/executable, inject shell commands, select files, dump traffic or disable TLS. Saved parameters are Keystore AES-GCM encrypted. HOME/token cache/transfer keys live under `noBackupFilesDir/cloudflared` (0700; upstream tokens 0600); child stdout/stderr and authentication URLs are not logged. Android trust anchors are atomically exported for Go TLS. Debug Actions → Clear Cloudflare Logins deletes `.cloudflared/*-token` files (app and organization JWTs) and stale companion `.lock`/`.url` files. Locks are checked against the owning PID/start time and Cloudflared's ten-minute authentication timeout; active or unreadable recent locks prevent clearing. It preserves CA/configuration, saved credentials and persistent ADB tunnel settings. Close Cloudflare sessions first; browser cookies remain under the browser's control.
- **Persistent wireless ADB**: `AdbDiscovery` reads ordinary-app `development_settings_enabled`, `adb_enabled` and `adb_wifi_enabled`; enabled USB or wireless ADB establishes developer access even when Horizon omits the generic developer-options setting. It serializes public NSD `_adb-tls-connect._tcp` discovery, accepts only this headset's interface addresses and checks its loopback port. ADB controls hide when developer mode is off. About can show editable setup before wireless discovery, but Start stays disabled until a port is found; the noncompact harness retains the original wireless-off hiding rule. `AdbTunnelSettings` stores token/hostname/bridge port encrypted under `noBackupFilesDir/adb-tunnel`; generated `config.yml` contains no token. `AdbTunnelService` uses `specialUse` foreground type (avoids dataSync's Android 15 time limit), an explicit Stop notification, process restart recovery and no automatic boot launch. The child receives `TUNNEL_TOKEN` through its environment and Android CA anchors; output is drained without recording raw configuration/secrets. A loopback-only relay (default 5555) closes existing clients on target changes/unavailability. Settings observers immediately disable forwarding on developer/wireless-off; every 15s the service rediscovers ADB, checks connector `/ready`, updates the relay, pauses the child if ADB is unavailable and retries dead children. User force-stop still stops the service.
- **Cloudflare ADB routing**: Supplied run tokens use remotely managed ingress; local YAML is a dashboard-rule reference, not a DNS/configuration API credential. Configure published hostname → `tcp://localhost:<bridge-port>` (or `127.0.0.1`) and its DNS record in Cloudflare. Client: `cloudflared access tcp --hostname <hostname> --url 127.0.0.1:<bridge-port>`, then `adb connect 127.0.0.1:<bridge-port>`. ## RDP Audio
- **Per-window spatial audio**: `QuestSpatialAudio` reads the Activity-scoped Horizon window-space UUID (`getWindowInfo(...).getHzSpaceUuid()`) and binds its owned AAudio session using `media.has` transaction 1 (`IHorizonAudioService.getSessionExt(int)`) and session transaction 2 (`IAudioSessionExt.setSpaceToken(byte[16])`, RFC 4122 UUID bytes). Descriptor checks, exception handling and stream-scoped binding caches preserve ordinary audio when these OS-private interfaces are absent/denied. No additional permissions or process split are required. Horizon resolves the source pose, window metadata and head tracking from that space.
- **Audio lifetime**: Each stream allocates an audio session ID. Native rdpsnd notifies the owning `FreeRDPBridge` before AAudio output starts and on close; format renegotiation/reopen binds the new session and drops the old cache. The Activity refreshes its cached space on focus/resume/movement and the existing 500ms audio poll. Successful requests are cached by session/space and live endpoint. Do not restore the process-global Vros token workaround: direct stream/window binding and audioserver-only transaction 24 did not preserve multi-window routing on v209 build `52641960021500520`. Legacy comparisons are debug-only.
- **Backend**: FreeRDP 3.32 upstream AAudio backends omit allocated session IDs; playback also requests performance mode NONE and a default 100ms cushion. Keep the `quest` provider for window association, latency, mute and diagnostics. Automated checks establish Spatial/EPS as the first active mixer with multiple windows, native pose changes and actual live RDP/keyboard-window lifecycle. James confirmed the deployed spatial audio works in the headset (2026-10-17); synthetic checks do not establish physical Home gestures or IME delivery.
- Playback lifetime: `quest_audio.cpp` serializes AAudio writes, close/open and volume updates. CMake applies two guarded teardown corrections to the upstream `rdpsnd` source in the build directory: join its playback worker before closing/freeing the device or DSP state. This prevents the native AudioTrack proxy crash observed during session teardown; upstream files stay unchanged. Android explicitly prohibits concurrent [AAudio close/read/write](https://developer.android.com/ndk/guides/audio/aaudio/aaudio).
- Playback delay: `rdpsnd` explicitly negotiates PCM and adaptive quality. AAudio requests a two-burst output buffer and reports actual queued render time to FreeRDP. The guarded rdpsnd correction includes queue age in WaveConfirm and discards audio older than 250ms while still parsing/acknowledging every PDU in order; PCM has no compressed-decoder dependency. Debug queue-age logs and hardware timestamp onset measurements retain no PCM. This bounds backlog recovery; it does not eliminate Windows' audio packetization delay.
- FreeRDP owns `rdpsnd`/`audin` negotiation and DSP; `quest_audio.cpp` supplies Android AAudio PCM devices. Static `rdpdr`/`rdpsnd` load through `LoadChannels`; `audin` loads only for a microphone-enabled, permitted connection. New RDP forms default Redirect Microphone off; saved profiles keep their chosen setting. Playback always redirects to Quest, independent of the legacy saved sound-redirection field.
- Setup checks `RECORD_AUDIO`; enabling the mic requests permission and denial leaves it off. A saved mic-enabled session waits for the permission result before creating its surface/connection, then connects without capture if denied. This override does not rewrite the saved profile.
- Toolbar speaker mute always appears; mic mute appears for effective microphone-enabled sessions. Mute sends silence per session. The mic turns red only while unmuted and the capture backend receives samples after a remote recording request; channel registration alone does not indicate recording. Capture stops on channel closure/session teardown.
- Confirmed unsupported capture shows a white mic with a red circle/slash; selecting it opens the host-support message and leaves mute unchanged. Host evidence is read from app-private `files/rdp-host-capabilities.json`, matching the profile host against verified aliases and a successful Windows `TSAudioCaptureAllowed=0` result. Missing evidence/idle capture stays unknown, with normal mute controls; actual capture clears a stale blocked state for that session. RDP has no general idle-host capture-support advertisement, so silent refusal cannot be automatically classified from a timeout.

## Threading Model & Performance
- Multiwindow RDP keeps the reconnect dialog on the owner monitor. Other monitors show a grey input-blocking `Disconnected` overlay while the shared session is disconnected or reconnecting; it clears after the new connection's monitor layout and surfaces are ready. `-e rdpMonitorReconnectOnly true` checks two live windows, touch blocking, retained Activity identities and overlay removal after one shared reconnect. Physical appearance remains a wearer check.
- **RDP monitor windows**: `RdpMonitorSession.kt` owns one FreeRDP connection per session UUID, with stable monitor IDs/document Activities and transient keyed native surfaces. Capability-gated Add desktop waits for actual window presentation and a surface, then serializes complete Display Control layouts. Copied GFX monitor arrays commit geometry; generation-bound crops and pointer offsets share that topology. Shared media/clipboard/reconnect/capture outlive primary closure; audio stays at primary and transfers on closure. Native CPU snapshot is shared across independently cropped outputs. Only settled visible Home poses drive approximate touching rows/columns, with room-gravity height and horizontal-only heading projection; hidden tray poses are ignored and native outputs suspend/rebind through restoration; panel placement/recovery are automatic and Add never becomes a Retry button. Signed host coordinates normalize to positive rendering/input atlas coordinates. Native drag handoff starts 64px inside a relevant edge and shares one session-owned held button. Optional hand-toolbar pick-up/drop holds that button across separate clicks/hover on same-session desktops, with Escape/cancel/timeout/teardown cleanup and missing-UP isolation. Ordinary in-panel drags stay unchanged. Both native windows receive START in automation; physical continuous traversal remains a wearer check. Host geometry/primary flags, atlas bounds and native crop/paint revisions are checked for drift independent of host array order; wire identities stay in creation order. Mixed-size rows align their closest room pair independently of which panel supplies connectivity. Rows preserve horizontal relationships, including diagonals, and use a tiny horizontal stagger to avoid corner-only monitor contacts rejected by the tested Windows host. One automatic retry precedes recovery to the last host-confirmed topology or a simple row; confirmed remote/local agreement restores Add, with a placement-failure Toast on fallback. Rejected geometry is suppressed until changed or explicitly retried. Pending synchronization retains input on the current confirmed host/crops; actual atlas/crop/paint disagreement blocks input, without full-atlas fallback. State-only `RdpInput` pointer-down diagnostics distinguish bridge rejection from UI delivery. Local surface repairs avoid remote reset loops. `RdpLayoutTransition` freezes each displayed TextureView before resize/topology changes, coalesces retries under one dimmed mask with an animated loading ring, waits for settled panel poses and 1.5 seconds of confirmed host/crop/paint agreement, then fades the retained image out over 320 ms. Mask entry releases held pointer input; the mask consumes desktop touches and leaves toolbar actions accessible; bitmap snapshots are bounded to 1600x1000 and released after fade/disposal. Terminal failure/disconnect/reconnect clears the mask. New size/placement changes can restart terminal recovery. Server/protocol/32 Mi-pixel atlas and aggregate limits, no fixed Home window count. Live production harness (validated on 3S; Quest 3 geometry/input checks pass, live run awaits a saved RDP profile): `adb -s <QUEST_3S_SERIAL> shell am instrument -w -e rdpMonitorsOnly true com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`; first saved full-desktop RDP connection, results/PNGs in cache `rdp-monitor-windows/`. `-e rdpLayoutGeometryOnly true` checks bounds/connectivity/order and the minimization pose tracker without opening Activities. [Ownership, constraints, evidence and manual checks](docs/rdp-multi-monitor.md).
- A full-frame TextureView scales via Compose `Modifier.graphicsLayer { scaleX = zoom; scaleY = zoom; translationX = panX; translationY = panY }`. To bypass `ViewFactoryHolder` bounds-clipping of scaled coordinates at high zooms, touch input is captured on an unscaled screen-space overlay `Box` (`Modifier.fillMaxSize().pointerInteropFilter`). Screen pointer coordinates `(eventX, eventY)` are inverted through `mapScreenToDesktop`: `tx = (eventX - panX - w / 2f) / zoom + w / 2f; ty = (eventY - panY - h / 2f) / zoom + h / 2f; rdpX = (tx * actualWidth / w); rdpY = (ty * actualHeight / h)`. The right-click hold indicator draws in unscaled screen coordinates directly under the controller pointer ray dot. Drag touch-slop uses standard physical touch slop. After a 300 ms debounce, DisplayControl requests matching remote resolution.
- Home panel pose observation uses the headset framework's activity-scoped volumetric window listener, loaded reflectively for Android compatibility. Position/orientation changes reveal the session toolbar; registration is removed on Activity destruction. IME insets control the keyboard modifier row and hidden text-field lifecycle.
- Surface recreation replaces the native surface while retaining the connection. Session disposal joins native network/render workers before freeing the context.
- **Codecs:** FreeRDP 3.x static channels load through `LoadChannels` and a custom addin provider. Hardware AVC444v2 decoding through Qualcomm's low-latency MediaCodec decoder is verified on Quest 3. AVC444 reconstruction and YUV/RGBA conversion remain CPU work; Progressive/RemoteFX software decoders remain available.
- **Codec logging:** `RdpContext` owns the original SurfaceCommand handler and 16 atomic throttle counters, constructed/destructed with the native context and reset on GFX channel connection. GDI owns `RdpgfxClientContext::custom` as `rdpGdi*`; the wrapper recovers its session through `gdi->context`. Codec log lines include the session pointer.
- **MediaCodec implementation:** `app/src/main/cpp/h264_mediacodec.c` replaces the upstream experimental backend through the root CMake configuration; the FreeRDP submodule stays unchanged. Supports padded I420/NV12 output, bounded waits, and lazy decoder allocation. Populates FreeRDP 3.32's `YUVWidth`/`YUVHeight` from validated plane dimensions, required by AVC444v2 bounds checks and reconstruction. Leaving those fields zero produces white GFX surfaces despite successful hardware decoding. Only I420 output has been exercised on-device.
- **Build:** arm64 only; native debug builds retain symbols and use `-O2` so codec/conversion performance is representative.
- **Target:** 2-4 concurrent sessions on Quest 3. Background throttling remains planned.

## Phased Build Plan

**Build-ordering rule: De-risk first.** The highest-risk item is the FreeRDP NDK build and the JNI bridge. This must be spiked and validated before anything else.

### Spike Phase: JNI & Native Bridge
- **Goal**: Successfully compile FreeRDP 3.32.1+ via Android NDK and render a single session frame to an Android Surface.
- **Gotchas**: Set `HOME` env dir to `filesDir` before init; compile with internal crypto flags.
- **Acceptance**: A rudimentary Android activity connects to an RDP server and renders the desktop.

### Phase 1: Basic RDP
- **Goal**: Connect to one Windows PC, full desktop in a spatial window, mouse/keyboard input, securely saved credentials.
- **Acceptance**: Shippable single-session RDP client on Horizon OS.
- **Deferred**: Multiple sessions, RemoteApp, Webcam, SSH.

### Phase 2: Multiple Sessions
- **Goal**: N concurrent RDP sessions.
- **Implementation**: Reconnecting to an active host reuses the existing session window. A genuinely new session spawns a new FreeRDP instance (requires server CALs or multiple accounts).
- **Acceptance**: Two desktop windows visible simultaneously in passthrough.

### Phase 3: RemoteApp Support (RAIL)
- **Goal**: Individual remote applications appear as their own floating windows.
- **Acceptance**: Launching a RemoteApp opens a new Spatial Window without the full desktop background.

### Phase 4: Webcam Support
- **Goal**: Redirect Quest cameras into the RDP session (`rdpecam`).
- **Acceptance**: Remote Teams/Zoom can access the Meta Avatar virtual webcam or room camera.

### Phase 5: SSH Windows
- **Goal**: Terminal sessions alongside RDP windows.
- **Acceptance**: SSH connection opens a window running the Termux VT emulator.

### Phase 6: Tunneling & Proxies (RDP Cloudflared implemented)
- **Goal**: Support RDP/SSH/VNC through Cloudflared, SOCKS5 and HTTP, plus persistent Cloudflared tunnels; connection choices are limited to None/Cloudflared/SOCKS5/HTTP.
- **Implementation**: Saved RDP/SSH/VNC Cloudflared uses the bundled Android arm64 binary, authenticated loopback forwarding and session-owned teardown. HTTP CONNECT and SOCKS5 CONNECT route all three protocols. Persistent developer ADB tunneling has gated Settings, token storage and foreground-service health checks. General-purpose persistent tunnels remain pending. Arbitrary commands are not selectable.
- **Acceptance**: Functional None/Cloudflared/SOCKS5/HTTP choices per connection and persistent Cloudflared foreground services.
