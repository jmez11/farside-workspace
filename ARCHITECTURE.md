# Architecture: Farside Workspace

## Product Vision
**Farside Workspace** is a native RDP, SSH and VNC client for Meta Quest (Horizon OS). Its defining feature is that every remote session and RemoteApp is its own spatial window, which can be placed freely in the standard Home/passthrough environment without entering a custom VR world. It is designed as a plain-language, no-bells-and-whistles productivity utility.

## Project Identity
- Repository/Gradle project: `farside-workspace`; product: Farside Workspace; Android application/namespace: `com.farside.workspace`. Kotlin sources and JNI symbols share that namespace. Local checkout: ``C:\dev\farside-workspace``. Runtime storage/Keystore/session URI names use ``farside``; bundled Cloudflared and its parser share ``FARSIDE_*`` process markers and the ``2026.5.1-farside`` version. Renaming the package creates a separate installation without migrating the previous app data.

## Module Map
1. **App / UI Layer (`app`)**: Jetpack Compose and Meta VR Layout SDK for Compose Spatial Windows. Manages the connection launcher (main panel) and spawns new Spatial Windows for each session.
2. **Session Manager**: Coordinates active connections, handles panel lifecycle (spawning/closing windows), and routes input. Spawns one FreeRDP instance per RDP session.
3. **RDP Core (`freerdp-jni`)**: JNI bridge to FreeRDP 3.32.1 (`bf217a504e54cc719880c228e82353382cd7d4fa`; submodule tracking branch `3.32.x`). Handles session lifecycle, video stream decoding (MediaCodec AVC/H.264), input event injection, RAIL window mapping, and camera redirection (`rdpecam`). Upstream tag is unmodified; the former pin's local Android CMake fixes are no longer needed by this build.
4. **SSH / Terminal Core (`ssh-core`)**: SSHJ for secure transport, combined with Termux's GPLv3 terminal-emulator stack for VT100/xterm emulation. Dynamic PTY window resizing via `sshShell.changeWindowDimensions(columns, rows, width, height)`. Floating movable toolbar with 3-second auto-fade, pin toggle, zoom font size adjustment (`8sp..32sp`), reset zoom, and keyboard toggle matching the RDP design. Bottom-attached companion spatial window (`RemoteKeyboardPanel`, 251.2dp tall, minimum 512dp wide) with full `RemoteExtraKeys` modifier latching, VT escape sequences, and shared `RemoteImeEditor` text routing while preserving the main terminal window's geometry (`adjustNothing`). Supports public key authentication using saved SSH keys, password authentication, and interactive terminal login fallback when credentials or keys are not provided.
5. **Settings & Storage**: Saved credential/profile/proxy passwords and SSH private keys/passphrases use randomized AES-GCM encryption via a non-exportable Android Keystore key (`CredentialManager`); app-private preferences store ciphertext, with plaintext legacy fields migrated in one durable transaction by `ProfileManager`. `SavedSshKey.kt` encrypts both private keys and optional passphrases with Keystore. Key usage requires no biometric prompt. Credentials, SSH keys, and preferences are excluded from cloud backup and device transfer because the key is device-bound. Passwords and keys are decrypted in app memory only when authenticating; hashing cannot replace recoverable credentials. Credential and key editing never preloads saved passwords/passphrases into input fields: blank preserves existing values, new text replaces them. Masked inputs request password keyboard type with autocorrect disabled; password state is not saved in Activity instance state.
6. **Network & Proxy Subsystem**: Saved RDP/SSH/VNC profiles support HTTP CONNECT, SOCKS5 CONNECT and Cloudflared. RDP passes proxy settings to FreeRDP; VNC passes a connected Java socket FD to LibVNCClient for standard and Mac authentication; SSHJ uses `HttpConnectSocketFactory` or `Socks5SocketFactory`. `CloudflaredTunnel.kt` owns one child and private loopback listener per session. Persistent developer ADB access uses `AdbTunnelService`. Arbitrary proxy commands and persistent general-purpose tunnels remain unimplemented.

## Connection profile editor
- New Add Connection forms select RDP and initialize the editable port to 3389; switching to SSH or Mac/VNC applies their respective port defaults. Editing a profile retains its saved port.
- The profile form title uses Add Connection for a new profile and Edit Connection when an existing profile is supplied.
- Invalid field tooltips listen for hover on the validation wrapper around the input, so the host field receives pointer hover even when its inner text control handles events. Once a field's validation wrapper activates (`message != null`), `FormValidationField` keeps the wrapper `Box` mounted when the error clears during editing so the inner `TextField` stays in the same composition slot and retains focus and the active IME session.
- Starting network discovery, opening the discovered-host picker, or choosing a discovered RDP/VNC host clears focus from any active text field first, and selecting a discovered host populates the Connection Name whenever it is blank/whitespace, `"New Profile"`, matches the previous host, or was previously auto-filled from discovery.

## VNC / Screen Sharing
- `libvncserver` is an unmodified upstream git submodule at `app/src/main/cpp/libvncserver`, pinned at `98aaee0560baa0332339b2ef464ea96ed9b9b28c` (0.9.15 plus upstream fixes); `vnc/CMakeLists.txt` builds client-only static LibVNCClient into `vnc-jni`. Software ZRLE/zlib/Tight decode; libjpeg-turbo 3.1.2 is pinned and built separately through ExternalProject (no MediaCodec). Upstream GPLv2 license and JPEG notices ship under `assets/licenses`.
- `vnc_bridge.cpp` owns each client's framebuffer, input queue, password, two ZlibHex streams, native window and worker/render threads. Only the worker accesses the RFB decoder/socket; completed frames copy to a protected RGBA buffer paced at 30fps. Cursor shape/mask/hotspot and position are session-owned and composited into the window buffer, preserving decoded desktop pixels. A fallback arrow covers peers such as macOS that omit cursor shapes; explicit zero-sized shapes hide it. Surface replacement is synchronized; disconnect signals/shuts down the socket, joins both threads, then frees client/window/JNI refs. `VncBridge` serializes handles with teardown; callbacks post to Android's main thread.
- Request order: ZRLE, Tight, ZlibHex, then Hextile/RRE/Raw. Generated upstream source copies add bounded ZlibHex decoding, reject non-type-2 security on the legacy path, and fix partial-field socket reads. NewFBSize reasserts pixel format/encodings before a full replacement frame, including same-size resets after Mac login. The Apple account path completes type-30 RFB 3.8/DH/MD5/AES authentication in Kotlin using platform crypto, then passes the authenticated socket to LibVNCClient at ClientInit. The type-2 path remains native and retains its 1 to 8 Latin-1 password rule; no-auth and types 33/35/36 are never selected.
- VNC profiles default to port 5900 and persist a SavedCredential link plus `vncAuthMode` and optional `sftpPairProfileId`. New Mac/VNC forms select `MAC_USER`; existing profiles retain their saved mode, and older JSON without a mode loads as `VNC_PASSWORD`. Neither password nor account username is stored in VNC profile JSON. Existing Keystore AES-GCM and PIN gating apply. The VNC editor requires a username/password credential for Mac mode and only offers SSH profiles with `enableSftp` checked for pairing. A valid paired profile enables the Files toolbar action; a deleted or SFTP-disabled pair hides the action. Add/Edit Connection requires a display name and uses per-field red validation and delayed hover tooltips without inline error rows. Mac mode distinguishes a missing credential, username, and password; VNC password mode distinguishes a missing credential, empty password, and invalid 1–8 Latin-1 password. Host, port, proxy, Cloudflared parameters, and SSH jump-route errors attach to their fields. The LAN discovery button and result picker have input hit-test priority over validation fields below them, keeping both scanning and selection tappable after invalid Save.
- Secure Mac console unlock is not implemented. Live DH/RSA1 probes with Apple `003.889`/enhanced ClientInit still showed the existing user's lock screen; that host's SessionSelect path requires a different authenticated/console UID. Its credential-bearing SessionSelect command is not an established unlock operation for the current console. Type-33 retest after host settings change (2026-10-13) again authenticated successfully with flags=2 and remained locked after five seconds without input (`build/verification/vnc-lock/retry-type33/`). Do not substitute automatic password keystrokes. See `build/verification/vnc-lock/findings.md`; `macLogin` below is synthetic UI login, not protocol-level unlock.
- `VncSessionScreen` uses `DesktopSessionScreen`/`DesktopSessionBridge`, the existing RDP unscaled pointer overlay/inverse zoom-pan map, `RdpPointerGesture`, `RdpControllerScroll`, floating toolbar and shared IME/key panel. The existing Compose pointer observer forwards unpressed Move/Enter events to VNC; pointerInteropFilter does not provide these hover events through its touch callback. XT events translate to X11 keysyms (WIN = Command/Super); Unicode uses RFB Unicode keysyms. The shared toolbar adds Files only for an existing paired SSH profile; audio/camera/RDP storage/RemoteApp controls are absent for VNC. Server framebuffer resizes are followed; local window resizing scales rather than changing Mac resolution.
- Standard Latin-1 ClientCutText/ServerCutText clipboard is bidirectional with echo suppression; UTF-8 extended clipboard pseudo-encoding is negotiated when supported. Cloudflared reuses the session child/loopback lifecycle with `access tcp`.
- `NetworkScanner.scanLocalNetworkForVnc(Context)` browses `_rfb._tcp.` with Android NSD for 5s, serializes resolves, removes lost services and stops on completion/cancellation. The VNC editor shows macOS user before VNC password and enables local Mac discovery only in macOS user mode; both idle and scanning labels say Macs. Its picker saves the Bonjour service name and advertised port; direct sessions browse again to resolve the current address. Credentials are entered/saved separately. Screen Sharing must be enabled on Mac to advertise; mDNS stays on the LAN and does not cross VLANs/Tailscale.
- Harness: `adb shell am instrument -w -r -e vncMode fixture|picker|discovery|live|macPicker|pointer|macSetup|macShortUser|macPairSetup|macWrong|macLogin|danglingPair [-e vncProfile <id>] com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`. `macShortUser` probes Apple account auth with the short SSH username; `macPairSetup` updates the named saved credential, creates a same-Mac SSH profile, and pairs it to VNC. `macWrong` asserts rejected SecurityResult and the localized session callback; `macLogin` logs in using the saved credential and captures the desktop; `danglingPair` uses a disposable VNC profile to assert the Files action is absent when SSH is deleted. `fixture` exercises real JNI type-2 rendering/input/clipboard on test-only servers. Cache: `vnc-results.txt`, `vnc-frame-<encoding|live>.png`, `vnc-login-*.png`. Synthetic input does not establish physical keys/gestures or wearer appearance.
- Reset fixtures assert format/ordered-encoding negotiation before full requests, both same-size and growing framebuffers, then full/partial ZRLE rendering with a persistent zlib stream (`vnc-reset-*.png`). Opt-in `vncMode login` is a diagnostic for the known <MAC> 1280x800 account chooser; `vncPassword` supplies the transient macOS account password for this mode only, without saving/logging it. It captures the transition, rejects a black desktop, opens/closes a Finder window with synthetic Command keys and asserts both redraws (`vnc-login-*.png`). Do not run login/pointer modes against an already logged-in desktop or a different account layout.

## SSH forwarding and terminal preferences
- `ssh/SshConnectionManager.kt` owns one reference-counted SSHJ transport and optional `access ssh` Cloudflared child per profile ID. Terminal shells and SFTP channels share it; a consumer releases only its own channels/lease. Last release disconnects and closes the tunnel off the main thread. Existing saved-key/password/interactive terminal authentication is extracted, with `PromiscuousVerifier` unchanged; SFTP requires saved authentication and reports failures inline.
- `SshForward.kt` persists local/remote/SOCKS5 TCP rules, source/destination ports, Auto/IPv4/IPv6 listener family, loopback/other-host access and enabled state. `SshForwardingDialog.kt` is shared by the profile's **Port forwarding** submenu and session toolbar: route cards, status, toggle, edit/remove and a separate editor. Profile setup saves with the parent form; session edits save immediately. Remote other-host access requires server GatewayPorts permission.
- `SshForwarding.kt` uses SSHJ direct/forwarded channels, async reconciliation and session-owned sockets/channels. Saved rules start after authentication; changes release/recreate affected listeners without reconnecting the shell. Dynamic forwarding implements SOCKS5 CONNECT framing over SSHJ (no UDP). Auto local listeners support both loopback families; explicit IPv6 never silently falls back. Bind errors appear per rule.
- SSH profiles persist font size (8-32), opacity (0.2-1) and scrollback (100-50,000 lines). Profile terminal settings configure history capacity; the floating settings-menu button is removed. Termux preserves screen/cursor and configured capacity across resize. Pointer drag/selection handles auto-copy when enabled; SSH selection offers Copy/Paste with Termux's More action disabled; remote mouse-tracking applications retain mouse input. Compose owns the SSH InputConnection; TerminalView cannot take native text focus during taps/selection. Physical hardware (Bluetooth/USB) keyboard `KeyEvent`s are captured by Compose's focused root container (`focusRequester`, `focusable`, `onKeyEvent`) and dispatched directly to `terminalView.onKeyDown` / `onKeyUp`, preserving VT escape codes, key handling, and combining accents while keeping Back navigation mapped to the launcher. SSH writes snapshot Termux's reusable buffer into one ordered session-owned writer, including primary/backspace/alternative sequences.
- The terminal-drawn right scrollbar has a 24dp click/drag target spanning the transcript. Reading history suppresses jumping to live on incoming output; returning to the bottom resumes it. `SshControllerScroll.kt` accepts Horizon wheel/rotary scroll and Y/RY/HAT_Y joystick axes through Activity dispatch (without a redundant window-focus guard). Fractional wheel deltas accumulate; joystick deflection repeats local history scrolling at approximately 2?80 lines/s. Neutral, focus loss, pause and teardown stop repeats.
- **SSH pointer menus**: Opt-in Termux floating Paste-only action at right-click (touch or generic secondary-button events) or stationary pointer hold when selection is inactive. Active selection offers Copy only; drag still auto-copies. Paste routes through the session clipboard callback, keeps Compose IME focus, is disabled for an empty clipboard, and closes on selection/detachment. Other Termux consumers keep their existing menus.
- Harness: `adb shell am instrument -w -r -e sshFeaturesOnly true com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`; `sshOnly` covers toolbar/keyboard regressions. The feature suite runs an ephemeral test-only Apache MINA SSH server on Quest: encrypted tunnel traffic/lifecycle/errors, saved-rule startup, profile/session persistence, scrollback, synthetic drag clipboard plus Copy-only selection/right-click/timed-hold Paste and exact SSH bytes, Activity-routed wheel/rotary/right-stick events, draggable scrollbar oldest/live, actual Compose InputConnection commit/replacement before/after selection, ordered 160-character SSH input. Clipboard read permission and simulated unworn IME visibility are test-only. Cache artifacts: `ssh-features-results.txt`, `ssh-forwarding-dialog.png`, `ssh-forwarding-editor.png`, `ssh-terminal-features.png`, `ssh-scrollback-oldest.png`; latest host copies: `build/verification/ssh-input/`. Synthetic events/InputConnection calls do not verify physical controller/ray hit testing or the real Horizon long-press popup; passthrough appearance remains manual. Loopback fixtures do not verify a user's SSH server forwarding policy.

## SSH SFTP files
- `ConnectionProfile.enableSftp` defaults false and is forced false for non-SSH profiles during JSON read/write; it uses the same all-files-access permission request/result flow as Redirect Storage. Launcher **Files** appears only when a saved SSH profile enables SFTP; it opens a dark list panel in the existing movable window, gated by the app-wide PIN before profile enumeration. Only enabled SSH profiles appear. No new app dependency.
- Platform spike selected the fallback: Horizon Files omits third-party roots; root VIEW opens Android DocumentsUI rather than Horizon Files. Static spike provider was removed from the final APK. Evidence/source snapshot: `build/verification/sftp/spike/`.
- `sftp/SftpFilesPanel.kt`: home listing, path/back navigation, name/size/mtime, directory-first sorting, headset upload picker, file and folder download, rename/delete/new-folder actions and replacement prompts. Folder download opens Android's document-tree picker, scans the remote tree, reports scan/folder/file progress, then copies readable files/subfolders with aggregate byte progress. Existing destination entries stop the operation; symlinks and unavailable entries are skipped. Failures are logged under `SftpFiles` with the exception and stack trace. File deletion never recursively removes directories or follows links. UI, directory metadata and transfer work are separated; network/file IO runs on IO workers. Compact layout gives the connection name its own single-line row, wraps action buttons, and truncates long paths.
- Listing speed/UX: `list` stats only symlinks (other entries reuse `ls` attributes); it does not count or report items while listing. The panel keeps a per-connection in-memory listing cache (cleared on connect/root; mutations refresh the current folder and drop affected keys); Refresh always re-reads. The browser offers Name/Date sorting. SSH sessions with `enableSftp` run a background SFTP probe over the shared transport after the shell starts (`SshTerminalSession.onConnected`); `SftpFilesControl` in the SSH toolbar shows a folder icon on success, or a red circle-backslash on failure; no icon until probed.
- `sftp/SftpSession.kt`: one SSHJ SFTP channel per operation over the shared SSH lease; streamed get/put and progress without whole-file buffering. Downloads use pending MediaStore rows; uploads use unique sibling staging files. Cancelling closes operation streams/channels, keeps SSH alive, and preserves the old destination during transfer. Publication is a short non-cancellable step; remote replacement uses atomic rename when supported, otherwise backup/rename/rollback. A lost connection during non-atomic publication can leave a `.previous` recovery file. Panel close/screen-off cancel work, then release the last lease after upload cleanup. No background-transfer service.

## Windowing Model
- **Proxy choices**: None, Cloudflared, SOCKS5 and HTTP are selectable. HTTP CONNECT and SOCKS5 CONNECT work for RDP, SSH and VNC with optional proxy credentials. Invalid proxy host/port is rejected. RDP uses FreeRDP settings; guarded CMake build-copy corrections fix upstream 3.32.1's IPv4/DNS target checks for HTTP/SOCKS5 and HTTP Basic credential length without changing the submodule. VNC standard and Mac paths detach the connected Java socket FD into LibVNCClient. SOCKS4/LOCAL/TELNET are legacy decode values and reject direct fallback. Harness: `-e proxiesOnly true` verifies RDP HTTP/SOCKS5 and SSH SOCKS5 socket routing; `-e rdpHttpLive true` and `-e rdpSocksLive true` connect the saved laptop through local HTTP/SOCKS5 relays; `-e vncMode proxy|proxyLive` checks local standard/Mac HTTP/SOCKS5 fixtures and the saved Mac account through an HTTP relay; `-e httpProxyOnly true` authenticates saved `nano via http` through saved `ssh.<USER_DOMAIN>` forwarding. Physical Horizon interaction remains manual.
- **PIN protection**: App PIN remains the default session access gate for credentials/SSH keys marked `requirePin`. The **Use headset passcode instead** switch is hidden while Quest blocks the app (`DeviceCredentialAuth.SYSTEM_PIN_SWITCH_VISIBLE=false`); dormant activation requires a successful framework `BiometricPrompt` callback of type `DEVICE_CREDENTIAL` before atomically setting `system_pin_enabled` and removing the old App PIN verifier/backoff. Failed/canceled/unavailable prompts preserve the existing mode and verifier. System mode never falls back to App PIN or bypasses protection when its verifier is absent. Disabling an item's protection in system mode always requests fresh authentication. `DeviceCredentialAuth.kt` caches only a monotonic authorization deadline for an optional five minutes; screen-off, detected lock/unavailability, rejection and process death revoke it. Requests cancel on dialog disposal and time out after 30 seconds. Credential AES-GCM encryption remains the existing non-authentication-bound Keystore key; this is a session access gate, not a completed cryptographic migration.
- **Quest system-authentication restriction (2026-10-11)**: This headset has a configured Horizon passcode; ordinary UID 10092 sees `BiometricManager.canAuthenticate(DEVICE_CREDENTIAL)=0` while `KeyguardManager.isDeviceSecure=false`. Actual requests reach Quest's `BPVrStatusBar`, but `VrLockscreenGatingUtil` rejects `com.farside.workspace` because it is not on the biometric-prompt inmarket allowlist (`GK/DC=false`). Availability is insufficient to enable the feature. App PIN remains usable; system activation is blocked on this OS until Meta permits the app. Do not change OS gatekeeper flags or request signature-only passcode privileges as a workaround. Successful OS unlock, real five-minute reuse, passcode removal/reset and authentication-bound Keystore compatibility remain unverified.
- **System authentication harness**: `adb shell am instrument -w -r -e systemPinMode policy com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation` checks the synthetic monotonic cache boundaries/lock/removal states, real RDP/SSH/VNC startup gates/cancellation actual Settings switch absence and OS rejection from a test-hosted production activation dialog with retained App PIN/mode. It uses fixture preferences restored exactly; it never reads or types the headset passcode. Cache evidence: `system-pin-results.txt`, `system-pin-activation.png`; host evidence: `build/verification/system-pin/`. `systemPinMode live` requires Meta's OS gate to allow Farside and a wearer entering the real passcode within 30 seconds; current OS blocks it.
- **Saved credentials & SSH keys**: User Management supports Edit/Save Changes/Cancel Edit, retaining the credential UUID. Settings "SSH Keys" tab supports adding, editing, and deleting saved SSH keys with multiline private key input, optional passphrase, and Require PIN gating. `ConnectionProfile.credentialId` and `ConnectionProfile.sshKeyId` persist profile links. SSH connection profiles do not require credentials; username, password, and SSH key are optional, falling back to interactive terminal login when omitted. Harness: `adb shell am instrument -w -e sshKeysOnly true com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation` validates in-memory PIN cache expiry and memory wiping, AES-GCM ciphertext persistence, optional SSH credentials, Settings SSH Key management, PIN toggle protection with 5-minute checkbox, wrong PIN rejection, 5-minute prompt bypass, and profile SSH key dropdown selection. `credentialsOnly` validates credential lifecycle, App PIN setup/backoff, and session gates.

- **RAIL Support**: Each RemoteApp published via RAIL appears as its own floating window, with server-authoritative z-order and transparency support.
- **Lifecycle**: Closing a session terminates its connection. Add/Edit Profile exposes Reconnect Automatically in the shared General section for RDP, SSH and Mac/VNC; its saved default is off. When enabled, Material's circular indicator counts down five seconds; retries recreate the connection and surface/terminal. RDP creates a fresh certificate verifier per attempt because closing a connection permanently closes its verifier. VNC has no app certificate verifier; SSHJ creates its host-key verifier per connection. Failed retries continue to offer reconnect. Local teardown suppresses the disconnect callback.
- **Launch placement**: `SessionWindowLauncher.kt` creates independent tasks/session ordinals; clicks use fresh Home placement and native drop uses Home's launch options. - **Launcher gestures**: Normal cards click/tap to open and long-pinch/hold to start spatial placement drag. `ConnectionSpatialDrag.kt` uses Home's global Android activity drag (`application/vnd.android.activity`, immutable one-shot PendingIntent and UserHandle). A complete outlined preview reads SessionActivity's pixel sizing metadata, then Android window-layout/dp fallback; current preview and initial session both measure 1280x800px. Home supplies drop options to non-exported SessionActivity; slots, connection startup and PIN gates begin after drop. Cancellation frees tokens; launcher stays available. ## Security
- **Cloudflared**: fixed Android arm64 executable in nativeLibraryDir, argv-only ProcessBuilder, validated DNS hostname, and extra-parameter allowlist: service-token ID+secret or Cloudflare Access authentication headers. Reject the whole input on unknown/unsafe options; users cannot override listener/hostname/executable, inject shell commands, select files, dump traffic or disable TLS. Saved parameters are Keystore AES-GCM encrypted. HOME/token cache/transfer keys live under `noBackupFilesDir/cloudflared` (0700; upstream tokens 0600); child stdout/stderr and authentication URLs are not logged. Android trust anchors are atomically exported for Go TLS. Debug Actions → Clear Cloudflare Logins deletes `.cloudflared/*-token` files (app and organization JWTs) and stale companion `.lock`/`.url` files. Locks are checked against the owning PID/start time and Cloudflared's ten-minute authentication timeout; active or unreadable recent locks prevent clearing. It preserves CA/configuration, saved credentials and persistent ADB tunnel settings. Close Cloudflare sessions first; browser cookies remain under the browser's control.
- **Persistent wireless ADB**: `AdbDiscovery` reads ordinary-app `development_settings_enabled` / `adb_wifi_enabled`, serializes public NSD `_adb-tls-connect._tcp` discovery, accepts only this headset's interface addresses and checks its loopback port. Settings hides the section when developer mode is off and shows setup fields only with wireless debugging on. `AdbTunnelSettings` stores token/hostname/bridge port encrypted under `noBackupFilesDir/adb-tunnel`; generated `config.yml` contains no token. `AdbTunnelService` uses `specialUse` foreground type (avoids dataSync's Android 15 time limit), an explicit Stop notification, process restart recovery and no automatic boot launch. The child receives `TUNNEL_TOKEN` through its environment and Android CA anchors; output is drained without recording raw configuration/secrets. A loopback-only relay (default 5555) closes existing clients on target changes/unavailability. Settings observers immediately disable forwarding on developer/wireless-off; every 15s the service rediscovers ADB, checks connector `/ready`, updates the relay, pauses the child if ADB is unavailable and retries dead children. User force-stop still stops the service.
- **Cloudflare ADB routing**: Supplied run tokens use remotely managed ingress; local YAML is a dashboard-rule reference, not a DNS/configuration API credential. Configure published hostname → `tcp://localhost:<bridge-port>` (or `127.0.0.1`) and its DNS record in Cloudflare. Client: `cloudflared access tcp --hostname <hostname> --url 127.0.0.1:<bridge-port>`, then `adb connect 127.0.0.1:<bridge-port>`. This carries existing wireless ADB TLS/authentication through the relay; it does not publish a raw public TCP port.
- Discovery filters stale advertisements by probing each local candidate on a dedicated worker before selection; failed candidates advance the serialized queue. Service-loss callbacks cannot erase the verified snapshot during teardown. Ten actual 3s discovery/loopback cycles and UI Start/Stop/readiness passed with current 36369 and stale 45681 both advertised; evidence: `build/verification/adb-discovery-fix/`. Physical wireless-switch and long-sleep transitions remain manual.
- Quiet Access login preflight handles valid credentials, cached JWTs and interactive login before RDP handshake timeout. Its standard encrypted Cloudflare transfer flow retrieves/caches user tokens; ACTION_VIEW opens only HTTPS transfer URLs for the profile hostname with the expected CLI path/query. The bundled source adaptation tolerates a missing CF-Access-Domain header using the original hostname, still requiring an audience. Routes without Access metadata proceed to the normal verified WebSocket handshake. Closing/failure cancels that session's child; surface replacement retains it. Listener readiness comes from a post-bind marker, with bounded startup/authentication waits. Original RDP host/certificate verification stays active through loopback.
- **RDP certificates**: FreeRDP `VerifyX509Certificate` uses external management; ignore-certificate and legacy RDP security fallback are disabled. JNI sends the full PEM chain to `RdpCertificateVerifier`; Android's default X509 trust manager checks server trust/validity and OpenSSL checks DNS/IP identity against the original profile host (not a tunnel's loopback endpoint).
- Unverifiable certificates show Connect/Cancel, an unchecked remember option, reasons and expandable issuer/dates/SHA-256 details. App-private `rdp_certificates` preferences persist the exact leaf fingerprint and PEM/details per case-insensitive host+port. Matching saved exceptions are reused only after attempting verification; a changed invalid certificate prompts again and shows the prior fingerprint. Valid replacements pass without an exception. Session-only Connect never updates trust; Cancel/dismiss rejects. Session disposal cancels a pending confirmation before worker teardown.
- **Credentials**: Passwords are AES-GCM encrypted with Android Keystore keys. Linked profiles persist only a credential UUID, never a copied username/password. Legacy snapshots migrate only on an unambiguous credential match. Reads resolve the central record; dangling IDs return empty authentication and reject startup/reconnect. This prevents the native AudioTrack proxy crash observed during session teardown; upstream files stay unchanged. Android explicitly prohibits concurrent [AAudio close/read/write](https://developer.android.com/ndk/guides/audio/aaudio/aaudio).
- Playback delay: `rdpsnd` explicitly negotiates PCM and adaptive quality. AAudio requests a two-burst output buffer and reports actual queued render time to FreeRDP. The guarded rdpsnd correction includes queue age in WaveConfirm and discards audio older than 250ms while still parsing/acknowledging every PDU in order; PCM has no compressed-decoder dependency. Debug queue-age logs and hardware timestamp onset measurements retain no PCM. This bounds backlog recovery; it does not eliminate Windows' audio packetization delay.
- FreeRDP owns `rdpsnd`/`audin` negotiation and DSP; `quest_audio.cpp` supplies Android AAudio PCM devices. Static `rdpdr`/`rdpsnd` load through `LoadChannels`; `audin` loads only for a microphone-enabled, permitted connection. New RDP forms default Redirect Microphone off; saved profiles keep their chosen setting. Playback always redirects to Quest, independent of the legacy saved sound-redirection field.
- Setup checks `RECORD_AUDIO`; enabling the mic requests permission and denial leaves it off. A saved mic-enabled session waits for the permission result before creating its surface/connection, then connects without capture if denied. This override does not rewrite the saved profile.
- Toolbar speaker mute always appears; mic mute appears for effective microphone-enabled sessions. Mute sends silence per session. The mic turns red only while unmuted and the capture backend receives samples after a remote recording request; channel registration alone does not indicate recording. Capture stops on channel closure/session teardown.
- Confirmed unsupported capture shows a white mic with a red circle/slash; selecting it opens the host-support message and leaves mute unchanged. Host evidence is read from app-private `files/rdp-host-capabilities.json`, matching the profile host against verified aliases and a successful Windows `TSAudioCaptureAllowed=0` result. Missing evidence/idle capture stays unknown, with normal mute controls; actual capture clears a stale blocked state for that session. RDP has no general idle-host capture-support advertisement, so silent refusal cannot be automatically classified from a timeout.

## Threading Model & Performance
- A full-frame TextureView scales via Compose `Modifier.graphicsLayer { scaleX = zoom; scaleY = zoom; translationX = panX; translationY = panY }`. To bypass `ViewFactoryHolder` bounds-clipping of scaled coordinates at high zooms, touch input is captured on an unscaled screen-space overlay `Box` (`Modifier.fillMaxSize().pointerInteropFilter`). Screen pointer coordinates `(eventX, eventY)` are inverted through `mapScreenToDesktop`: `tx = (eventX - panX - w / 2f) / zoom + w / 2f; ty = (eventY - panY - h / 2f) / zoom + h / 2f; rdpX = (tx * actualWidth / w); rdpY = (ty * actualHeight / h)`. The right-click hold indicator draws in unscaled screen coordinates directly under the controller pointer ray dot. Drag touch-slop uses standard physical touch slop. After a 300 ms debounce, DisplayControl requests matching remote resolution.
- Home panel pose observation uses the headset framework's activity-scoped volumetric window listener, loaded reflectively for Android compatibility. Position/orientation changes reveal the session toolbar; registration is removed on Activity destruction. IME insets control the keyboard modifier row and hidden text-field lifecycle.
- Surface recreation replaces the native surface while retaining the connection. Session disposal joins native network/render workers before freeing the context.
- **Codecs:** FreeRDP 3.x static channels load through `LoadChannels` and a custom addin provider. Hardware AVC444v2 decoding through Qualcomm's low-latency MediaCodec decoder is verified on Quest 3. AVC444 reconstruction and YUV/RGBA conversion remain CPU work; Progressive/RemoteFX software decoders remain available.
- **Codec logging:** `RdpContext` owns the original SurfaceCommand handler and 16 atomic throttle counters, constructed/destructed with the native context and reset on GFX channel connection. GDI owns `RdpgfxClientContext::custom` as `rdpGdi*`; the wrapper recovers its session through `gdi->context`. Codec log lines include the session pointer.
- **MediaCodec implementation:** `app/src/main/cpp/h264_mediacodec.c` replaces the upstream experimental backend through the root CMake configuration; the FreeRDP submodule stays unchanged. Supports padded I420/NV12 output, bounded waits, and lazy decoder allocation. Populates FreeRDP 3.32's `YUVWidth`/`YUVHeight` from validated plane dimensions, required by AVC444v2 bounds checks and reconstruction. Leaving those fields zero produces white GFX surfaces despite successful hardware decoding. Only I420 output has been exercised on-device.
- **Build:** arm64 only; native debug builds retain symbols and use `-O2` so codec/conversion performance is representative.
- **Target:** 2-4 concurrent sessions on Quest 3. Background throttling remains planned.

## Phased Build Plan

**Build-ordering rule: De-risk first.** The highest-risk item is the FreeRDP NDK build and the JNI bridge. This must be spiked and validated before anything else.

### Spike Phase: JNI & Native Bridge
- **Goal**: Successfully compile FreeRDP 3.32.1+ via Android NDK and render a single session frame to an Android Surface.
- **Gotchas**: Set `HOME` env dir to `filesDir` before init; compile with internal crypto flags.
- **Acceptance**: A rudimentary Android activity connects to an RDP server and renders the desktop.

### Phase 1: Basic RDP
- **Goal**: Connect to one Windows PC, full desktop in a spatial window, mouse/keyboard input, securely saved credentials.
- **Acceptance**: Shippable single-session RDP client on Horizon OS.
- **Deferred**: Multiple sessions, RemoteApp, Webcam, SSH.

### Phase 2: Multiple Sessions
- **Goal**: N concurrent RDP sessions.
- **Implementation**: Reconnecting to an active host reuses the existing session window. A genuinely new session spawns a new FreeRDP instance (requires server CALs or multiple accounts).
- **Acceptance**: Two desktop windows visible simultaneously in passthrough.

### Phase 3: RemoteApp Support (RAIL)
- **Goal**: Individual remote applications appear as their own floating windows.
- **Acceptance**: Launching a RemoteApp opens a new Spatial Window without the full desktop background.

### Phase 4: Webcam Support
- **Goal**: Redirect Quest cameras into the RDP session (`rdpecam`).
- **Acceptance**: Remote Teams/Zoom can access the Meta Avatar virtual webcam or room camera.

### Phase 5: SSH Windows
- **Goal**: Terminal sessions alongside RDP windows.
- **Acceptance**: SSH connection opens a window running the Termux VT emulator.

### Phase 6: Tunneling & Proxies (RDP Cloudflared implemented)
- **Goal**: Support RDP/SSH/VNC through Cloudflared, SOCKS5 and HTTP, plus persistent Cloudflared tunnels; connection choices are limited to None/Cloudflared/SOCKS5/HTTP.
- **Implementation**: Saved RDP/SSH/VNC Cloudflared uses the bundled Android arm64 binary, authenticated loopback forwarding and session-owned teardown. HTTP CONNECT and SOCKS5 CONNECT route all three protocols. Persistent developer ADB tunneling has gated Settings, token storage and foreground-service health checks. General-purpose persistent tunnels remain pending. Arbitrary commands are not selectable.
- **Acceptance**: Functional None/Cloudflared/SOCKS5/HTTP choices per connection and persistent Cloudflared foreground services.
