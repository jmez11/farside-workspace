# Mac clipboard sharing

## Findings

- [Apple Screen Sharing](https://support.apple.com/guide/mac-help/share-the-screen-of-another-mac-mh14066/mac) exposes Edit → Use Shared Clipboard, including text and images. It is separate from Universal Clipboard.
- [RFB 3.8 / RFC 6143, §§7.5.6 and 7.6.4](https://www.rfc-editor.org/rfc/rfc6143.html) defines bidirectional Latin-1 text clipboard messages. Farside's LibVNCClient path already handles those and negotiates extended UTF-8 clipboard support on compatible servers.
- Apple's modern pasteboard needs its private extension. The [iShareScreen wire implementation](https://github.com/renegadelink/iShareScreen/blob/main/src/isharescreen/proxy/protocol/clipboard.py) documents an interoperable reverse-engineered implementation, rather than an Apple API guarantee. Its function bodies correct stale module-header descriptions: enable mode **1**, fetch **8 bytes**. Standard ClientCutText updates a legacy scrap rather than modern NSPasteboard according to that investigation.
- Farside previously returned success without sending Mac streaming clipboard text, discarded incoming `0x1f` archives, and ignored clipboard-change notifications.

## Implementation

`MacClipboard.kt` enables monitoring (`0x15`), fetches initially and on MiscStatus command2 (`0x0b`), and sends/receives zlib SYNC_FLUSH pasteboard archives (`0x1f`) inside the existing authenticated encrypted control stream. Outbound uses `public.utf8-plain-text`; inbound prefers UTF-8, with BOM-aware/default-BE UTF-16 fallback. Aliases are metadata, not clipboard content. Images, files, promise-only metadata and empty archives do not replace Android text.

Outbound text is capped at1MiB UTF-8; incoming compressed/uncompressed archive decoding at32MiB. Larger archives, such as screenshots, are drained without allocation up to a64MiB wire limit, leaving the desktop connected. Fields/counts and inflation are bounded. Fully consumed malformed archives are ignored; negative sizes or wire bodies beyond64MiB fail the session rather than desynchronize parsing. Large outbound messages split into60000-byte records, serialized with other input. Existing stream reassembly handles fragmented inbound headers/payloads. The latest decoded archive is retained within the session (at most32MiB), allowing exact pasteboard preservation/readback; it is cleared on close. Logs contain sizes/support status only, never clipboard contents.

`DesktopClipboardSync` binds the existing desktop UI to Android ClipboardManager, preserves text echo suppression and ignores callbacks queued after disposal. Failed sends no longer become the last-successful value. VncBridge routes streaming text to the Apple session and posts incoming text only for its current session. Native VNC retains its standard clipboard path; **Apple clipboard sharing is unavailable after ordinary VNC fallback**. No helper, SSH command or Mac setting change is required for this implementation.

Safari follow-up (Oct23): a three-line webpage selection arrived as a22,391,849-byte rich pasteboard bundle. The original2MiB cap skipped its text too; the32MiB cap accepts the observed bundle. Quest3S live readback decoded its text and restored the entire archive. JVM regression includes text alongside a webarchive beyond the old cap. Larger bundles still drain without replacing Android text.

## Validation

- JVM: `:app:testDebugUnitTest`, including `MacClipboardTest` for wire bytes, Unicode, UTF-16, flavor preference, metadata/empty/image-only input, malformed lengths/archives, bounds and large outbound text.
- Device: `adb -s <QUEST> shell am instrument -w -r -e vncMode macClipboardFixture com.farside.workspace.test/com.farside.workspace.RdpResizeInstrumentation`. Owned loopback peer exercises the production session record stream, clipboard codec, outgoing bridge and shared Android clipboard binding. Incoming golden vector was generated with the independent Python encoder above; outbound is independently decoded. Tests fragments, >190KB text across records, notification/fetch, echo suppression, malformed archive recovery, bounds and close. Authentication/media negotiation is deliberately bypassed; this does not establish live macOS compatibility.
- Surrounding UI/JNI regression: `vncMode inlineFixture`; shared input: `inputOnly true`. Run modes sequentially. Background clipboard permission is test-only and does not establish physical Horizon focus/keyboard delivery.
